# P3 调试方法：单函数、单帧、场景、系统四层

> P3 是纯 Python 算法层，调试不需要 ROS。真正需要的是**分层**：
> 单函数用 pytest 钉住语义，单帧用 CLI 看中间量，场景回放看时间上的
> 滞回/恢复，最后才是 P4 的 ROS 联调。本文说明每层怎么用、图怎么读。

---

## 1. 为什么不能只靠一种调试

| 层次 | 能回答的问题 | 不能回答的问题 |
| --- | --- | --- |
| 单函数 / pytest | 某个分支在给定输入下返回什么 | 连续 20 帧会不会抖、会不会积累状态 |
| 单帧 CLI | 这一帧的目标/己方检测、FSM、护栏、输出分别是什么 | 下一帧状态机会怎么迁移 |
| 场景回放 | 目标丢失→L1→L2→恢复的完整时间线、指令跳变、中枢覆盖 | 真实 ROS 时延、DDS、QoS |
| 系统联调（P4） | 话题是否通、时间戳来源、中枢真实行为 | 算法内部每个分支的精确语义 |

所以推荐顺序是：**先用 pytest 定位“哪个函数/哪个分支错了”，再用单帧
CLI 看“这一帧的中间量”，最后用场景回放确认“连续多帧不抖”。** 反过来
只盯场景图，容易被中枢 2s 保留、TRACK 视觉优先等外部行为带偏。

## 2. 第一层：单函数 / 单模块（pytest）

这是“传统单个调试”，适合验证 `validators`、`degrade_fsm`、
`degrade_policy`、`safety_guard` 的单个分支。

```bash
cd /home/silensky/Projects/ros2_ws

# 只跑一个文件
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/test_degrade_fsm.py

# 只跑名字里带 extrapolating 的用例
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test -k extrapolating

# 失败时直接进 pdb；或在代码里临时写 breakpoint()
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/test_degrade_policy.py --pdb
```

每个用例开头都有“场景 / 预期 / 实测”输出，失败时先看这三行，再看断言
位置。常用入口：

- `test_validators.py`：输入分类（FRESH/STALE/INVALID/…）；
- `test_degrade_fsm.py`：级别迁移、滞回、时间戳倒退、恢复；
- `test_degrade_policy.py`：四级 × 七动作的关键路径；
- `test_safety_guard.py`：六步护栏与顺序；
- `test_replay_anomaly.py`：任务书 11 组异常回放。

**适用**：怀疑某个判断条件写错、边界值不对、某个动作语义被破坏。

## 3. 第二层：单帧（simulate_p3.py --tick）

`simulate_p3.py` 现在支持只打印某一帧前后的完整链路：

```bash
cd /home/silensky/Projects/ros2_ws

# 场景 C 的第 47 帧（t=2.35s，己方断流刚触发 L3）
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --tick 47 --no-plot

# 看“节点默认 max_step=None”时同一帧的差异
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --tick 47 --no-plot --params default
```

输出分两部分：

1. **±3 帧的简表**：`own_before / target_true / level / anomaly /
   plan_point / published / source`，用来判断“这一帧是不是迁移点”；
2. **选中帧详情**：按真实调用顺序列出

```text
输入己方 -> P1 目标状态 -> 目标检测 -> 己方检测 -> FSM 迁移
        -> P3 结果（point/reason/guard_notes）
        -> 适配层兜底点 plan_point
        -> 中枢实际指令 published
```

读的时候按这个顺序排查：

1. `target_visible / ego_dropped`：这一帧到底缺了什么；
2. `目标检测 / 己方检测`：是 STALE、INVALID、TIME_REVERSED 还是 MISSING；
3. `FSM 迁移`：`previous -> current`、`reason`、`changed`；注意
   `bad_frames/good_frames` 的滞回；
4. `P3 结果`：`level / reason / point / guard_notes`；
5. `plan_point` 与 `published`：前者是适配层兜底后的点，后者是中枢实际
   指令；两者不同通常不是 P3 算错，而是中枢的 2s 保留/TRACK 视觉优先。

常用参数：

```bash
# 列出场景
... simulate_p3.py --list

# 只跑一个场景
... simulate_p3.py --scenario B

# 每帧导出 CSV，便于 pandas/Excel 对照
... simulate_p3.py --scenario C --csv /tmp/p3_c.csv --no-plot

# 不画图，跑得快
... simulate_p3.py --no-plot
```

**适用**：场景图上看到某个时刻“不该降级却降了”，或想知道某一帧到底
是哪个检测器/哪个 reason 触发的。

## 4. 第三层：场景回放（整段）

```bash
# 三个场景全跑，打印摘要 + 级别迁移 + 判定，并更新文档图
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py

# 只跑 C，并导出每帧 CSV
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --csv /tmp/p3_c.csv
```

场景回放看四件事：

1. **级别迁移时刻**是否和策略表一致（A：2.55 L1 → 2.60 L2 → 2.70
   NORMAL；B：3.55 L1 → 4.00 L2 → 4.60 NORMAL；C：2.35 L3 → 2.80 L2
   → 2.90 NORMAL）；
2. **输出是否跳变**：标定 `max_step` 后 `max_jump <= max_step`；
3. **ATTACK 是否尾随**：C 的 `tail_points` 必须是 0；
4. **中枢保留指令**期间飞了多远：默认 `max_step=None` 时 C 会飞 5.58m，
   标定后 0m；这解释“为什么 no_plan 了飞机还在动”。

**适用**：确认滞回、恢复、以及“算法正确但系统行为看起来不对”的差异。

## 5. 图怎么读

图由 `simulate_p3.py` 的 `plot_scene()` 用 matplotlib 生成（Agg 后端，
不弹窗，直接存 PNG）：

- 左图：`ax_path`，XY 轨迹；
- 右图：`ax_time`，级别阶梯；`ax_time.twinx()` 叠加距离红线；
- 浅色带：`axvspan` 标出遮挡/断流区间；
- 保存：`figure.savefig(out_path, dpi=150)`。

### 5.1 左图（XY 轨迹）

| 图例 | 含义 |
| --- | --- |
| `target true path`（灰色虚线） | 仿真里目标的真实路径（上帝视角，算法看不到） |
| `target visible sample`（灰点） | 目标可见时的采样点；遮挡期间没有点 |
| `NORMAL`（蓝线） | 无人机在 L0 时的航迹 |
| `EXTRAPOLATING`（橙线） | 无人机在 L1 时的航迹 |
| `HOLDING`（红线） | 无人机在 L2 时的航迹 |
| `NO_PLAN`（黑线） | 无人机在 L3 时的航迹 |
| `center command`（紫点） | 中枢实际发出的指令点（已经过中枢的 5m 环绕/2s 保留） |
| `start`（黑圆） / `end`（黑星） | 起点 / 终点 |

坐标是 ENU：x 向东，y 向北，单位米。左图用 `axis("equal")`，所以 B 场景
为了容纳 0～75m 的 x 范围，y 轴会被拉得很宽；**B 的 y 轴范围没有物理
含义**，只看“沿 x 轴追”即可。

### 5.2 右图（级别 + 距离）

| 图例/颜色 | 含义 |
| --- | --- |
| 蓝色阶梯 `degrade level` | P3 级别，纵轴从下到上：NORMAL → L1 → L2 → NO_PLAN |
| 红色实线 `own-target distance` | 无人机到目标真实位置的距离（右轴，米）；目标不可见时没有点，所以线会断 |
| 橙色带 `target occlusion` | 目标不可见区间（遮挡/丢失） |
| 灰色带 `ego dropout` | 己方状态断流区间；与橙色重叠时灰色在上 |

读图顺序：

1. 先看**浅色带**：橙色=目标丢了，灰色=己方断了；
2. 再看**蓝色阶梯**：在带内/带后是否按 L1→L2 或 L3→L2→L0 迁移；
3. 再看**红色距离**：距离在 L2 期间是否停止增长（说明保持点生效），
   在 L3 期间是否还在增长（说明中枢保留了旧指令，飞机还在飞）；
4. 最后看**紫色指令点与蓝色航迹**：两者分开说明中枢覆盖了 P3 的 TRACK
   点；这不是 P3 的降级计算错误。

### 5.3 三个场景的“看图要点”

**A（TRACK + 0.6s 遮挡）**

- 橙色带 2.0～2.6s；
- 蓝色阶梯在 2.55s 抬到 L1，2.60s 抬到 L2，2.70s 回 NORMAL；
- 紫色指令点在遮挡前就跳到目标东北侧（中枢 5m 环绕），蓝色航迹跟着
  紫色走；P3 的 TRACK 外推点被中枢 `latest_vision_target` 覆盖，所以
  图上会看到“P3 明明在 L1，飞机却没朝外推点飞”；
- 红色距离最后降到 1.48m：中枢 5m 环绕是软推力，目标转弯时会被甩近。

**B（INTERCEPT 追不上 + 1.5s 丢失）**

- 橙色带 3.0～4.5s；
- 蓝色阶梯 3.55s L1、4.00s L2、4.60s NORMAL；
- 红色距离一直在涨：目标 9m/s，己方 7.6m/s，本来就追不上；
- 蓝色航迹在 L2 期间停住（保持点），恢复后继续追；`fallback_tail`
  尾随点始终存在，这是 INTERCEPT 允许的语义。

**C（ATTACK + 目标转弯 + 0.5s 己方断流）**

- 橙色带 2.0～2.8s，灰色带 2.3～2.8s（灰色在上）；
- 蓝色阶梯 2.35s 直接到 NO_PLAN（己方断流优先），2.80s 回 HOLDING，
  2.90s 回 NORMAL；
- 黑色 L3 段在右图顶部；左图没有黑色长航迹，因为 L3 不产生新 P3 点；
- 紫色指令点在 L3 期间仍是旧点（中枢 2s 保留），所以飞机在默认
  `max_step=None` 时又飞了 5.58m；标定后为 0m；
- `tail_points=0`：ATTACK 没有尾随，符合契约。

## 6. 从场景问题回到 pytest

场景图只能说明“哪一段不对”，最终要落成可重复的单元测试：

1. 用 `--tick` 找到出问题的帧，记下 `target_status / ego_status /
   fsm.last_event / result.reason`；
2. 在 `test_replay_anomaly.py` 里按“正常 N 帧 → 异常 M 帧 → 恢复”
   重放这一段；
3. 断言级别序列、`result.point` 是否为 None、`reason`、`guard_notes`；
4. 如果是单帧几何问题，放 `test_degrade_policy.py` 或
   `test_safety_guard.py`；
5. 场景脚本里的“判定 A/B/C”保留为集成冒烟，不替代单元测试。

原则：**单帧/单函数测试钉语义，场景测试钉时间线；不要让场景图成为唯一
证据。**

## 7. 新增一个场景

在 `simulate_p3.py` 的 `build_scenarios()` 里加一项：

```python
{
    "name": "D",
    "title": "D: 你的场景",
    "action": "TRACK",              # TRACK / INTERCEPT / ATTACK
    "own_start": (0.0, 0.0, 10.0),
    "duration": 6.0,
    "max_step": 0.30,               # v_max * DT，用于标定组
    "target_fn": _target_d,         # t -> (x, y, z)
    "visible_fn": _visible_d,       # t -> bool
    "ego_dropout_fn": _ego_dropout_d,
}
```

然后：

```bash
... simulate_p3.py --scenario D --tick 40 --no-plot
... simulate_p3.py --scenario D --csv /tmp/p3_d.csv
```

如果这个场景要作为回归，给 `check_common` 或场景专属判定加一条断言，
并把预期迁移写进 `文档/P3降级策略.md`。

## 8. 第四层：P4 系统联调（现在不做）

P3 只保证 `PlanResult.level / anomaly / reason / guard_notes` 可读；
真正接进 `algorithm_node.py` 后，由适配层转成 ROS 日志。P4 才需要：

- `ros2 bag record` / `ros2 bag play` 回放真实目标与己方状态；
- mock 中枢，验证 `no_plan` 时中枢是否保留/悬停；
- 检查 `/drone_<id>/state` 是否被中枢回灌（E/F 自回灌）；
- 时延从哪个 stamp 算到哪个 stamp。

这些不在当前 P3 的 pytest 范围里，调试时不要用 P4 的问题去改 P3 的
降级语义。
