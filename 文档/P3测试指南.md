# P3 测试指南（不需要启动 ROS）

> 结论先说：**P3 是纯 Python 算法层，测试只需要 pytest，不需要 `ros2 launch`、
> 不需要启动中枢/飞机/仿真。** 你不需要手动输入任何命令；需要时由我执行，
> 下面是留档和复现用的规范。

当前测试结果：**162 passed**（宿主机 Python 3.12.3；Humble 容器 Python
3.10.12 各跑一遍）。

## 2. 怎么跑（三种方式）

### 2.1 宿主机直接跑 pytest（当前最常用）

前提：**不要 source ROS**，不要启动任何节点；只需要 `PYTHONPATH` 指向
算法包源码。

```bash
cd /home/silensky/Projects/ros2_ws
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q src/algorithm_pkg/test
```

期望输出最后一行：

```text
162 passed in 0.0x s
```

前面还会逐条打印“场景 / 预期 / 实测”，例如：

```text
- test_l1_track_uses_extrapolated_target
  场景：目标短暂丢失，仍在 t_extrap_max=1.0 内。
  预期：第 2 个过期帧进入 L1；TRACK 发外推点，不掉成 no_plan。
  实测：first.level=NORMAL, second.level=EXTRAPOLATING, point=(10.9,0,10)
```

### 2.2 Humble 容器里跑（交付环境）

按 `文档/Jazzy开发与Humble交付指南.md`，在容器 `/ws` 里：

```bash
source /opt/ros/humble/setup.bash
PYTHONPATH=src/algorithm_pkg python3 -m pytest -q src/algorithm_pkg/test
```

不需要 `colcon build` 也能跑 pytest；P3 不依赖 ROS 包编译。

如果使用一次性容器（推荐，避免旧容器挂载错）：

```bash
docker run --rm --network none \
  -v /home/silensky/Projects/ros2_ws:/ws -w /ws \
  --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -e PYTHONDONTWRITEBYTECODE=1 \
  osrf/ros:humble-desktop-full \
  bash -lc 'source /opt/ros/humble/setup.bash && \
            PYTHONPATH=src/algorithm_pkg \
            python3 -m pytest -q -p no:cacheprovider src/algorithm_pkg/test'
```

注意：旧的 `ros2_humble_dev` 容器虽然镜像正确，但它的 `/root/ros2_ws`
挂载是空的（指南里提过），不要直接用它跑；用上面的 `/ws` 挂载或按指南
重建容器。

### 2.3 只跑某一组

```bash
# 只看 P3 状态机
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/test_degrade_fsm.py

# 只跑包含 attack 的用例
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test -k attack
```

### 2.4 运动仿真（不是 pytest）

三个复杂场景的时间推进仿真（目标机动、遮挡、丢失、己方断流）单独放在：

```bash
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py
```

它会打印级别迁移、指令跳变、尾随点、中枢保留指令等指标，并把轨迹图
写到 `文档/figures/`。场景说明和结论见
`文档/P3三个复杂场景仿真.md`。这不是 pytest 用例，不影响 162 项结果。

单帧调试和 CSV 导出：

```bash
# 只看场景 C 第 47 帧（己方断流触发 L3 的那一帧）
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --tick 47 --no-plot

# 导出每帧记录，便于 pandas/Excel 对照
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --csv /tmp/p3_c.csv --no-plot

# 用节点默认 max_step=None 跑，观察“不限制跳变”时的差异
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 \
    src/algorithm_pkg/test/simulate_p3.py \
    --scenario C --params default --no-plot
```

单帧输出、图的颜色/图例、四层调试方法见 `文档/P3调试方法.md`。

仿真脚本额外依赖 matplotlib（宿主机已有 3.6.3）；P3 的 pytest 本身
不依赖 matplotlib。Humble 容器如果没装 matplotlib，只跑 pytest 即可。

### 2.5 静态检查（可选）

```bash
/usr/bin/python3 -m pyflakes src/algorithm_pkg/algorithm_pkg src/algorithm_pkg/test
/usr/bin/python3 -m pycodestyle --max-line-length=79 \
    src/algorithm_pkg/algorithm_pkg src/algorithm_pkg/test
```

两条命令都无输出即通过。

## 3. 输出怎么读

- `162 passed`：全部通过，验收基线。
- `FAILED 文件::用例`：看下面的断言失败位置；测试名和“场景/预期”能直接
  看出是哪个降级路径出的问题。
- `ModuleNotFoundError: No module named 'algorithm_pkg'`：忘了
  `PYTHONPATH=src/algorithm_pkg`。
- `file or directory not found: src/algorithm_pkg/test`：当前目录不是
  仓库根目录，或容器挂载错了。
- `numpy` 版本报错：P3 不使用 numpy；如果出现，是 ROS/Python 环境问题，
  按交付指南用容器 apt 的 numpy 1.x，不要 `pip install -U numpy`。

## 4. 启动规范（重点）

### 4.1 现在（P3）不需要“启动程序”

P3 的交付物是纯函数和测试：

- 没有 `ros2 launch`；
- 没有节点、话题、`/strategy/cmd`；
- 没有中枢、飞控、仿真。

所以**“测试”就是跑 pytest**，不存在“先启动哪个节点”的问题。

### 4.2 什么时候才需要启动 ROS

P4 把 `plan_with_degrade()` 接进 `algorithm_node.py` 之后，才需要启动节点。
规范命令（在 Humble 容器、仓库根目录）：

```bash
source /opt/ros/humble/setup.bash
colcon build --packages-select algorithm_pkg --symlink-install
source install/setup.bash
ros2 launch algorithm_pkg algorithm.launch.py
```

但要注意：**当前 `algorithm_node.py` 仍然只调用 P2 的 `plan()`，没有接
P3 的 `plan_with_degrade()`。** 现在就启动节点，只会跑 P1/P2 的逻辑，
看不到 `level/anomaly` 降级日志。P3 的接线是下一步（P4）的工作。

### 4.3 环境铁律

- 主机只编辑和 Git；ROS 只在 Humble 容器里跑；
- 不要在主机的 Jazzy 里 source / colcon / launch；
- 纯 pytest 不需要 source ROS，也不需要 colcon；
- 容器里不要 `pip install -U numpy`。

## 5. 你需要做什么

不需要输入命令。每次我改完代码，会跑：

1. 宿主机 `162 passed` 冒烟；
2. Humble 容器同一组 pytest；
3. `pyflakes` / `pycodestyle` 静态检查；

然后把结果贴给你。如果你只想看某一个场景，例如“ATTACK 丢失后会不会
尾随”，告诉我场景，我单独跑对应用例并把“场景/预期/实测”贴出来。
