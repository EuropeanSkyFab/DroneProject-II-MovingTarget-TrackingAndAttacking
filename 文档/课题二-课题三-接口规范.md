# 课题二与课题三：双向数据接口规范 (V2.0)

> **说明**：根据最新架构调整，课题三作为“战略中枢”下发个体战术指令；课题二作为“战术代理”执行具体动作，并向课题三回传己方集群状态用于态势显示。为保证双方模块顺利解耦与联调，现统一定义以下标准接口。

---

## 一、 课题三 至 课题二：战术指令接口

课题三作为战略指挥，直接指定具体无人机的战术动作。

- **发送方**：课题三（战略中枢）
- **接收方**：课题二系统集成节点（中枢）、规划节点
- **通信机制**：ROS 2 话题
- **Topic 名称**：`/strategy/cmd`
- **消息类型**：`std_msgs/msg/String` （内容为 JSON 格式字符串）
- **业务约定**：课题三通过此接口下发战术意图（如：指定1号机撞击）。课题二中枢与规划节点同时订阅，中枢据此切换大状态机，规划据此切换预测算法。
- **消息格式示例**：
```json
{
  "drone_id": "drone_1",
  "action": "ATTACK"
}
```

### ⚠️ 战术动作枚举（Action Enum）强制规范
为防止大小写混用或拼写错误导致中枢状态机解析失败，`action` 字段的字符串**必须严格**使用以下枚举值（全大写）：

1. **`TAKEOFF`**：起飞。指令无人机解锁并升至指定安全高度。
2. **`HOVER`**：悬停。指令无人机在当前坐标原地保持不动。
3. **`RETURN`**：返航。指令无人机触发失控保护/自动返航，飞回起飞点。
4. **`TRACK`**：跟随。尚未辨明目标身份，保持常规限幅与安全距离跟飞。
5. **`INTERCEPT`**：追击。已辨明敌意，解除常规限幅，全速切内圈卡位。
6. **`ATTACK`**：攻击。终极指令，彻底解除限幅，全速直线撞击目标。
7. **`RESUME_PATROL`**：恢复执行任务。具体内容待定。

## 二、 课题二 至 课题三：己方集群位姿接口

课题二向课题三高频广播己方无人机的实时状态，供 QGC 界面进行态势渲染。

- **发送方**：课题二系统集成节点（中枢）
- **接收方**：课题三（QGC 二次开发与态势显示）
- **通信机制**：ROS 2 话题
- **Topic 名称**：`/drone_<id>/state` （多机模式下例如：`/drone_1/state`, `/drone_2/state`）
- **消息类型**：`nav_msgs/msg/Odometry`（ROS 2 原生标准）
- **坐标系**：`header.frame_id` 为 `"world"`（全局 ENU 坐标系，单位：米）

### 消息字段与物理含义解析

1. **时间与身份标识**
   - `header.stamp`：时间戳（精确到纳秒），UI 渲染依此排序以保证动画平滑。
   - `header.frame_id: "world"`：代表数据使用全局 ENU（东-北-天）坐标系。
   - `child_frame_id`：无人机唯一身份标识（如 `"drone_1_base_link"`），UI 据此区分不同飞机并上色。
2. **空间坐标与姿态**
   - `pose.pose.position (x, y, z)`：x为向东距离，y为向北距离，z为相对高度（正数代表离地高度，单位：米）。
   - `pose.pose.orientation (x, y, z, w)`：四元数姿态。UI 转欧拉角后获取偏航角（Yaw），用于画出机头指向。
3. **运动速度**
   - `twist.twist.linear (x, y, z)`：线速度（米/秒），用于显示速度矢量。
   - `twist.twist.angular (x, y, z)`：角速度（弧度/秒），代表转向快慢。

### 完整数据示例

以下为实际发送到 ROS 2 话题的 `Odometry` 数据示例（注：实际数据中 `covariance` 协方差数组全为 `0.0`，UI 解析时直接无视即可）：

```yaml
header:
  stamp: 
    sec: 1793015504
    nanosec: 281928854
  frame_id: "world"
child_frame_id: "drone_1_base_link"
pose:
  pose:
    position: {x: 10.5, y: 20.0, z: 5.0}
    orientation: {x: 0.0, y: 0.0, z: 0.707, w: 0.707} # 代表机头朝正东（Yaw=90度）
twist:
  twist:
    linear: {x: 2.0, y: 0.0, z: 0.0}   # 正以2m/s向东平飞
    angular: {x: 0.0, y: 0.0, z: 0.1}  # 缓慢向右转向
```

## 三、 课题二 至 课题三：无人机遥测状态接口

由于 `Odometry` 消息中不包含电池信息，为了满足课题三界面实时显示状态的需求，课题二额外广播无人机电池状态话题。

- **发送方**：课题二系统集成节点（中枢）或 桥接节点
- **接收方**：课题三（QGC 二次开发与态势显示）
- **Topic 名称**：`/drone_<id>/battery`
- **消息类型**：`sensor_msgs/msg/BatteryState`（ROS 2 原生标准）

### 核心字段解析
- **percentage (float32)**：电池剩余百分比（0.0 ~ 1.0）。例如 0.55 代表剩余 55%。
- **voltage (float32)**：当前电池电压（V）。
- **temperature (float32)**：电池温度（摄氏度）。
- **power_supply_status (uint8)**：当前供电状态（1 = 充电中，2 = 放电中，3 = 未充电，4 = 满电）。

### 数据示例
```yaml
header:
  stamp: {sec: 1793015504, nanosec: 281928854}
  frame_id: "drone_1_base_link"
voltage: 22.4
temperature: 35.5
percentage: 0.85    # 剩余电量 85%
power_supply_status: 2  # 正在放电
```

## 四、 课题二 至 课题三：通信链路健康度接口

为了满足课题三“当连接不畅时调用其他 UAV”的战术调度需求，课题二向课题三高频广播链路健康度监控数据。

- **发送方**：课题二系统集成节点（中枢）
- **接收方**：课题三（QGC 二次开发与态势显示）
- **Topic 名称**：`/drone_<id>/link_status`
- **消息类型**：`diagnostic_msgs/msg/DiagnosticStatus`（ROS 2 原生标准状态监控消息）

### 字段解析与 UI 逻辑
- **level (byte)**：链路状态级别。
  - `0` (OK)：信号良好。
  - `1` (WARN)：信号微弱。
  - `2` (ERROR)：链路丢失（LOST）。
- **hardware_id (string)**：无人机标识（如 `"drone_1"`）。
- **name (string)**：状态描述（如 `"Link Status: GOOD"`）。
- **values (KeyValue[])**：键值对数组。包含两个核心物理量：
  - `key: "delay_ms"`：当前数据延迟（毫秒）。
  - `key: "rssi"`：信号强度（dBm，若无真实数据则填模拟值）。

### 数据示例
```yaml
level: 0
name: "Link Status: GOOD"
message: "All systems nominal"
hardware_id: "drone_1"
values:
  - key: "delay_ms"
    value: "35.5"
  - key: "rssi"
    value: "-65"
```

## 对接要求与扩展
1. 课题二中枢节点将高频持续广播 `/drone_<id>/state` 话题。
2. 课题三需编写对应的 ROS 2 订阅节点，提取数据接入 QGC。
3. 若课题三在界面上还需要显示其他状态（如电量、飞行模式），请及时提出，课题二中枢可追加自定义字段。
