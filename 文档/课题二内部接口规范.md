# 课题二内部数据接口规范 (V3.0 战术协同版)

> **给所有模块开发 AI 的提示**： 
> 本系统基于 ROS 2。请严格按照以下定义的话题名（Topic）和消息类型（Message Type）编写代码。 
> 严禁擅自修改接口名称或类型。如果你的模块需要输入，请订阅对应话题；如果需要输出，请发布到对应话题。 
> 课题二使用 uXRCE-DDS 通信方案，请勿使用 MAVROS。

## 1. 系统数据流向拓扑图

本系统采用严格域隔离与状态随数据流同步架构。课题三作为战略中枢，直接下发个体战术指令；课题二中枢（系统集成）作为安全总闸，负责将意图转化为具体的多机物理动作并做底层兜底。

```text
【战术指令域（外部输入）】
外部课题三 ➔ `/strategy/cmd` (JSON)
  ├─ (订阅) ➔ 【系统集成 (中枢)】（解析指令，切换大状态机）
  └─ (订阅) ➔ 【规划模块】（知晓任务，切换内部预测算法）

【目标感知域（外部输入）】
外部课题一 ➔ `topic1_adapter` ➔ `/external/target_detected` ➔ 【规划模块】
视觉模块 ➔ `/vision/target_pose` 
  ├─ (订阅) ➔ 【系统集成 (中枢)】（用于近距离锁定与云台计算）
  └─ (订阅) ➔ 【规划模块】（用于轨迹预测与拦截点计算）

【规划计算域（内部流转）】
规划模块 ➔ `/planning/target_pose` (带 action 标签的 JSON) ➔ 【系统集成 (中枢)】

【中枢调度与底层执行域（核心流转）】
【系统集成 (中枢)】
  ├─ `/drone_<id>/action` ➔ 【飞控 DDS 桥接】（下发状态标签：TRACK 限幅 / ATTACK 解除限幅）
  ├─ `/drone_<id>/fmu/in/trajectory_setpoint` ➔ 【飞控 DDS 桥接】（下发实际 ENU 坐标）
  └─ `/drone_<id>/fmu/in/gimbal_setpoint` ➔ 【飞控 DDS 桥接】（下发云台偏转角度）
  
【飞控 DDS 桥接】 ➔ PX4 飞控 ➔ 物理无人机执行

【反馈与监控域（向上回传）】
飞控 DDS 桥接 ➔ `/drone_<id>/state` (Odometry)
  ├─ (订阅) ➔ 【系统集成 (中枢)】（防撞计算、心跳监控）
  └─ (订阅) ➔ 【规划模块】（获取己方速度，计算预测拦截）

飞控 DDS 桥接 ➔ `/drone_<id>/battery` & `/link_status` ➔ 【系统集成 (中枢)】

【系统集成 (中枢)】 ➔ `/fleet/state` ➔ 外部课题三（用于多机态势与电量综合显示）

【传感器输入域（底层直连视觉）】
飞控 DDS 桥接 (Gazebo) ➔ `/drone_<id>/camera/image_raw` & `/camera_info` ➔ 【视觉模块】（用于 YOLO 识别与 2D 转 3D）
```

## 2. 核心接口与数据域定义

### 2.1 目标状态域（Target Domain - 敌方/靶机）

#### 接口 A：视觉高精度目标位姿
- **发送方**：视觉节点
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/vision/target_pose`
- **消息类型**：`geometry_msgs/msg/PoseStamped`
- **消息格式示例**：
```text
header:
  stamp: {sec: 123456, nanosec: 789}  # 必须填充真实时间戳
  frame_id: "world"                   # 必须为 world (全局 ENU)
pose:
  position: {x: 10.5, y: 20.0, z: 5.0}
  orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}
```
- **业务约定**：视觉节点输出敌方/靶机的绝对三维坐标。视觉模块只充当系统的“眼睛”，**绝不负责计算己方无人机的拦截点或偏移量**。目标丢失时停止发送。

#### 接口 B：外部宏观引导
- **发送方**：`topic1_adapter`
- **接收方**：规划节点
- **Topic 名称**：`/external/target_detected`
- **消息类型**：`geometry_msgs/msg/PoseStamped`

#### 接口 C：规划拦截目标点（基于 JSON 的指令携带）
- **发送方**：规划节点
- **接收方**：系统集成节点
- **Topic 名称**：`/planning/target_pose`
- **消息类型**：`std_msgs/msg/String`（内容为 JSON 格式字符串）
- **坐标系约定**：JSON 中的 `x, y, z` 必须为全局 ENU 坐标系（东-北-天）。
- **业务约定**：
  - 规划节点需结合中控战略指令计算预测拦截点。
  - 为避免引入复杂的自定义 `.msg` 文件，规划节点通过 JSON 携带“战术动作标签（action）”与“源头时间戳（stamp）”。
  - 若 `action` 为 `"ATTACK"`，中枢将强制切断常规限幅，全速撞击目标。
- **消息格式示例**：
```json
{
  "stamp": 1793015504.281,
  "x": 10.5,
  "y": 20.0,
  "z": 5.0,
  "action": "ATTACK" 
}
```
*(注：`action` 的枚举值暂定为 `"TRACK"` 或 `"ATTACK"`。)*


### 2.2 战略指令与己方状态域（Ego & Strategy Domain）

#### 接口 D：课题三战术指令（状态下发）
- **发送方**：外部课题三
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/strategy/cmd`
- **消息类型**：`std_msgs/msg/String`（内容为 JSON 格式字符串）
- **业务约定**：课题三直接指定个体无人机的战术动作。
- **消息格式示例**：
```json
{
  "drone_id": "drone_1",
  "action": "ATTACK"
}
```

#### 接口 E：本体位姿回传
- **发送方**：飞控 DDS 桥接节点
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/drone_<id>/state` （例如：`/drone_1/state`）
- **消息类型**：`nav_msgs/msg/Odometry`
- **业务约定**：中枢依赖此数据计算相对距离与下发指令；规划依赖此数据中的 `twist.linear` 速度信息，结合目标速度计算精准的拦截弹道。

#### 接口 F：态势广播
- **发送方**：系统集成节点
- **接收方**：外部课题三
- **Topic 名称**：`/fleet/state`
- **消息类型**：`nav_msgs/msg/Odometry`
- **业务约定**：中枢将己方集群的所有位姿统一打包或分包，发给课题三进行态势显示。

### 2.3 控制输出域（Control Domain）

#### 接口 G：飞行控制指令（多机版）
- **发送方**：系统集成节点
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/fmu/in/trajectory_setpoint`
- **消息类型**：`px4_msgs/msg/TrajectorySetpoint`
- **业务约定**：中枢根据扁平化状态机输出。
  - **TRACK 模式**：输出常规坐标，底层进行平滑比例限幅。
  - **ATTACK 模式**：直接输出规划给的拦截坐标，解除底层平滑限幅，全速撞击。

#### 接口 H：战术动作广播（限幅调节器）
- **发送方**：系统集成节点（中枢）
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/action` （例如：`/drone_1/action`）
- **消息类型**：`std_msgs/msg/String` （内容为纯字符串：`"TRACK"`, `"ATTACK"`, `"IDLE"` 等）
- **业务约定**：中枢在切换内部状态机后，向底层桥接广播当前的动作指令。桥接节点据此动态调整内部平滑限幅的 `max_step` 参数。
  - 收到 `"TRACK"`：恢复常规限幅。
  - 收到 `"ATTACK"`：解除限幅，配合接口 G 的坐标进行全速冲刺。
  - 严禁桥接节点越权直接订阅课题三的 `/strategy/cmd`。

#### 接口 I：云台协同指令
- **发送方**：系统集成节点
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/fmu/in/gimbal_setpoint`
- **消息类型**：`px4_msgs/msg/GimbalManagerSetPitchYaw`（暂定）
- **业务约定**：中枢根据视觉目标的像素偏差，在锁定模式下计算云台偏转角并下发。

### 2.4 传感器输入接口（底层至视觉）

本接口由飞控底层（或 Gazebo 仿真器）负责提供，视觉模块负责订阅，中枢节点不处理原始图像。此接口为全系统铁律。

#### 接口 J：相机原始图像（多机隔离）
- **发送方**：飞控 DDS 桥接节点 / Gazebo
- **接收方**：视觉节点
- **Topic 名称**：`/drone_<id>/camera/image_raw`（例如 `/drone_1/camera/image_raw`）
- **消息类型**：`sensor_msgs/msg/Image`
- **业务约定**：飞控同学必须确保仿真里的相机数据被桥接成了 ROS 2 原生标准消息，并且由于多机存在，必须使用带 `<id>` 的命名空间隔离，防止 3 架飞机的画面串流。

#### 接口 K：相机内参
- **发送方**：飞控 DDS 桥接节点 / Gazebo
- **接收方**：视觉节点
- **Topic 名称**：`/drone_<id>/camera/camera_info`
- **消息类型**：`sensor_msgs/msg/CameraInfo`
- **业务约定**：视觉节点必须读取该消息获取焦距、主点等物理参数，用于将二维像素（2D）反投影计算为三维全局坐标（3D）。

## 3. 坐标系规范（全系统铁律）
- **内部算法坐标系**：全系统（规划、中枢、视觉、外部转换）统一使用 ROS 标准的 **ENU 坐标系**（东-北-天，Z轴向上为正，单位：米）。
- **飞控坐标系**：PX4 底层使用 NED（北-东-地）。
- **坐标转换职责**：由底层的飞控 DDS 桥接节点统一负责将中枢发出的 ENU 坐标转换为 NED。其他任何模块严禁加坐标系转换逻辑。

## 4. 中枢大状态机（单层扁平化架构）
抛弃复杂的双层嵌套，中枢中枢直接根据 `/strategy/cmd` 以及规划数据中的状态标签，切换单层状态机：
1. **`IDLE` (待命)**：无视视觉与规划数据，给当前无人机发送原定悬停点。
2. **`TRACK` (追踪)**：视觉数据合法优先听视觉（近距离），视觉超时听规划。平滑限幅正常生效。
3. **`ATTACK` (撞击)**：切断视觉，强制采用规划模块的“预测拦截点”，并向桥接发送解除平滑限幅信号，控制指定无人机全速直线撞击目标。

## 5. 动力学参数与预测边界
规划模块不需要关心底层飞控 PID 曲线，只需基于中枢提供的理论物理极限进行轨迹计算（具体参数个数与内容根据实际情况定）：
- **巡航速度** (用于常规追踪)
- **撞击极速** (用于拦截提前量计算)
- **最大加速度**
- **最小转弯半径**
*(参数最终数值以飞机模型实测为准，中枢将以此设定底层的 `max_step` 限幅)*

## 6. 系统时间同步与延迟过滤规范（铁律）
*(与 V2.0 保持一致：因 WSL 环境限制，当前阶段全系统禁用 `use_sim_time`，使用系统真实时间。所有数据必须打上源头时间戳。视觉延迟 > 0.2s 或规划延迟 > 0.5s 直接丢弃。)*


## 补充  战术动作枚举（Action Enum）强制规范
为防止大小写混用或拼写错误导致中枢状态机解析失败，`action` 字段的字符串**必须严格**使用以下枚举值（全大写）：

1. **`TAKEOFF`**：起飞。指令无人机解锁并升至指定安全高度。
2. **`HOVER`**：悬停。指令无人机在当前坐标原地保持不动。
3. **`RETURN`**：返航。指令无人机触发失控保护/自动返航，飞回起飞点。
4. **`TRACK`**：跟随。尚未辨明目标身份，保持常规限幅与安全距离跟飞。
5. **`INTERCEPT`**：追击。已辨明敌意，解除常规限幅，全速切内圈卡位。
6. **`ATTACK`**：攻击。终极指令，彻底解除限幅，全速直线撞击目标。
7. **`RESUME_PATROL`**：恢复执行任务。具体内容待定。
