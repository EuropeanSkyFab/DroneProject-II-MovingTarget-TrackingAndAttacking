# 课题二内部数据接口规范 (V3.0 战术协同版)

> **给所有模块开发 AI 的提示**： 
> 本系统基于 ROS 2。请严格按照以下定义的话题名（Topic）和消息类型（Message Type）编写代码。 
> 严禁擅自修改接口名称或类型。如果你的模块需要输入，请订阅对应话题；如果需要输出，请发布到对应话题。 
> 课题二使用 uXRCE-DDS 通信方案，请勿使用 MAVROS。

## 1. 系统数据流向拓扑图

本系统采用严格域隔离与状态随数据流同步架构。课题三作为战略中枢，直接下发个体战术指令；课题二中枢（系统集成）作为安全总闸，负责将意图转化为具体的多机物理动作并做底层兜底。

```text
【战术指令域（外部输入）】
外部课题三 ➔ `/strategy/cmd` (JSON)
  ├─ (订阅) ➔ 【系统集成 (中枢)】（解析指令，切换大状态机）
  └─ (订阅) ➔ 【规划模块】（知晓任务，切换内部预测算法）

【目标感知域（外部输入）】
外部课题一 ➔ `topic1_adapter` ➔ `/external/target_detected` ➔ 【规划模块】
视觉模块 ➔ `/vision/target_pose` 
  ├─ (订阅) ➔ 【系统集成 (中枢)】（用于近距离锁定与云台计算）
  └─ (订阅) ➔ 【规划模块】（用于轨迹预测与拦截点计算）

【规划计算域（内部流转）】
规划模块 ➔ `/planning/target_pose` (带 action 标签的 JSON) ➔ 【系统集成 (中枢)】

【中枢调度与底层执行域（核心流转）】
【系统集成 (中枢)】
  ├─ `/drone_<id>/action` ➔ 【飞控 DDS 桥接】（下发状态标签：TRACK 限幅 / ATTACK 解除限幅）
  ├─ `/drone_<id>/fmu/in/trajectory_setpoint` ➔ 【飞控 DDS 桥接】（下发实际 ENU 坐标）
  └─ `/drone_<id>/fmu/in/gimbal_setpoint` ➔ 【飞控 DDS 桥接】（下发云台偏转角度）
  
【飞控 DDS 桥接】 ➔ PX4 飞控 ➔ 物理无人机执行

【反馈与监控域（向上回传）】
飞控 DDS 桥接 ➔ `/drone_<id>/state` (Odometry)
  ├─ (订阅) ➔ 【系统集成 (中枢)】（防撞计算、心跳监控）
  └─ (订阅) ➔ 【规划模块】（获取己方速度，计算预测拦截）

飞控 DDS 桥接 ➔ `/drone_<id>/battery` & `/link_status` ➔ 【系统集成 (中枢)】

【系统集成 (中枢)】 ➔ `/fleet/state` ➔ 外部课题三（用于多机态势与电量综合显示）

【传感器输入域（底层直连视觉）】
飞控 DDS 桥接 (Gazebo) ➔ `/drone_<id>/camera/image_raw` & `/camera_info` ➔ 【视觉模块】（用于 YOLO 识别与 2D 转 3D）
```

## 2. 核心接口与数据域定义

### 2.1 目标状态域（Target Domain - 敌方/靶机）

#### 接口 A：视觉高精度目标位姿
- **发送方**：视觉节点
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/vision/target_pose`
- **消息类型**：`geometry_msgs/msg/PoseStamped`
- **消息格式示例**：
```text
header:
  stamp: {sec: 123456, nanosec: 789}  # 必须填充真实时间戳
  frame_id: "world"                   # 必须为 world (全局 ENU)
pose:
  position: {x: 10.5, y: 20.0, z: 5.0}
  orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}
```
- **业务约定**：视觉节点输出敌方/靶机的绝对三维坐标。视觉模块只充当系统的“眼睛”，**绝不负责计算己方无人机的拦截点或偏移量**。目标丢失时停止发送。

#### 接口 B：外部宏观引导
- **发送方**：`topic1_adapter`
- **接收方**：规划节点
- **Topic 名称**：`/external/target_detected`
- **消息类型**：`geometry_msgs/msg/PoseStamped`

#### 接口 C：规划拦截目标点（基于 JSON 的指令携带）
- **发送方**：规划节点
- **接收方**：系统集成节点
- **Topic 名称**：`/planning/target_pose`
- **消息类型**：`std_msgs/msg/String`（内容为 JSON 格式字符串）
- **坐标系约定**：JSON 中的 `x, y, z` 必须为全局 ENU 坐标系（东-北-天）。
- **业务约定**：
  - 规划节点需结合中控战略指令计算预测拦截点。
  - 为避免引入复杂的自定义 `.msg` 文件，规划节点通过 JSON 携带“战术动作标签（action）”与“源头时间戳（stamp）”。
  - 若 `action` 为 `"ATTACK"`，中枢将强制切断常规限幅，全速撞击目标。
- **消息格式示例**：
```json
{
  "drone_id": "drone_1",
  "stamp": 1793015504.281,
  "x": 15.0,
  "y": 20.0,
  "z": 10.0,
  "action": "TRACK"
}
```
*(注：`action` 的枚举值暂定为 `"TRACK"` 或 `"ATTACK"`。)*


### 2.2 战略指令与己方状态域（Ego & Strategy Domain）

#### 接口 D：课题三战术指令（状态下发）
- **发送方**：外部课题三
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/strategy/cmd`
- **消息类型**：`std_msgs/msg/String`（内容为 JSON 格式字符串）
- **业务约定**：课题三直接指定个体无人机的战术动作。中枢内部维护 `drone_modes` 状态字典，收到指令后更新对应无人机的状态，并驱动并发状态机独立分发坐标。
- **消息格式示例**：
```json
{
  "drone_id": "drone_1",
  "action": "ATTACK"
}
```

#### 接口 E：本体位姿回传
- **发送方**：飞控 DDS 桥接节点
- **接收方**：系统集成节点、规划节点
- **Topic 名称**：`/drone_<id>/state` （例如：`/drone_1/state`）
- **消息类型**：`nav_msgs/msg/Odometry`
- **业务约定**：中枢依赖此数据计算相对距离与下发指令；规划依赖此数据中的 `twist.linear` 速度信息，结合目标速度计算精准的拦截弹道。

#### 接口 F：态势广播
- **发送方**：系统集成节点
- **接收方**：外部课题三
- **Topic 名称**：`/drone_<id>/state` 
- **消息类型**：`nav_msgs/msg/Odometry`
- **业务约定**：中枢将己方集群的所有位姿逐个打包，发给课题三进行态势显示。包含电量与链路状态。

### 2.3 控制输出域（Control Domain）

#### 接口 G：飞行控制指令（多机版）
- **发送方**：系统集成节点
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/fmu/in/trajectory_setpoint`
- **消息类型**：`geometry_msgs/msg/PoseStamped`
- **坐标系约定**：中枢输出的 `pose.position` 为全局 **ENU** 坐标系（东-北-天，单位：米）；`header.frame_id` 必须为 `"world"`。**飞控 DDS 桥接节点在接收后，必须负责将其转换为 PX4 使用的 NED 坐标系**，中枢不负责转换。
- **业务约定**：中枢根据扁平化状态机输出。
  - **INTERCEPT 模式**：初步接触限幅，高速追击拦截敌机。飞控桥接 INTERCEPT 档的实际限幅为：**速度上限 7.6 m/s**（`max_step_intercept = 0.38` × 20Hz）、位置误差上限 `max_tether = 2.4 m`、水平加速度前馈上限 `8.0 m/s²`、垂直速度上限 `3.8 / 4.0 m/s`（上/下）。
  - **ATTACK 模式**：彻底解除底层平滑限幅，全速撞击。ATTACK 档实际限幅为：**速度上限 12.4 m/s**（`max_step_attack = 0.62` × 20Hz）、`max_tether = 3.8 m`、水平加速度前馈上限 `10.0 m/s²`。
  - 完整三档参数见接口 H 的《限幅档位对照表》。

#### 接口 H：战术动作广播（限幅调节器）
- **发送方**：系统集成节点（中枢）
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/action` （例如：`/drone_1/action`）
- **消息类型**：`std_msgs/msg/String` （内容为纯字符串：`"INTERCEPT"`, `"ATTACK"` 等）
- **业务约定**：中枢在切换内部状态机后，向底层桥接广播当前的动作指令。桥接节点据此切换内部限幅档位。
  - 收到 `"INTERCEPT"`：切到 INTERCEPT 档 —— **速度上限 7.6 m/s**、`max_step_intercept = 0.38`、`gain_p = 1.8`、`max_tether = 2.4 m`。
  - 收到 `"ATTACK"`：切到 ATTACK 档 —— **速度上限 12.4 m/s**、`max_step_attack = 0.62`、`gain_p = 3.2`、`max_tether = 3.8 m`，配合接口 G 的坐标进行全速冲刺。
  - 收到除以上两个以外的指令（`TAKEOFF` / `TRACK` / `HOVER` / `RETURN` 等）：保持常规档 —— **速度上限 2.8 m/s**、`max_step_default = 0.14`、`gain_p = 0.40`、`max_tether = 0.9 m`。
  - 严禁桥接节点越权直接订阅课题三的 `/strategy/cmd`。

**限幅档位对照表**

源码依据：`src/flight_ctrl_pkg/flight_ctrl_pkg/px4_bridge_node.py` 的 `_select_max_speed()` 与 `_control_loop()` 档位分支；速度上限 = `max_step × _REF_STEP_HZ(20)`。

| 参数 | 常规档（TAKEOFF/TRACK/HOVER/RETURN） | INTERCEPT | ATTACK |
| :--- | ---: | ---: | ---: |
| `max_step_*`（20Hz 等效步长） | `0.14` | `0.38` | `0.62` |
| **速度上限 `max_speed`** | **`2.8 m/s`** | **`7.6 m/s`** | **`12.4 m/s`** |
| 位置误差上限 `max_tether` | `0.9 m` | `2.4 m` | `3.8 m` |
| 比例增益 `gain_p` | `0.40` | `1.8` | `3.2` |
| 位置死区 `deadband_m` | `0.22 m` | `0.12 m` | `0.06 m` |
| 垂直速度上限（上 / 下） | `3.0 / 2.5 m/s` | `3.8 / 4.0 m/s` | `4.5 / 5.5 m/s` |
| 水平加速度前馈上限 | `5.0 m/s²` | `8.0 m/s²` | `10.0 m/s²` |
| 垂直加速度前馈上限 | `3.5 m/s²` | `4.5 m/s²` | `5.5 m/s²` |

> **说明 1**：`max_step_*` 是按 20Hz 定义的等效步长；实际每周期步长由 `max_speed × dt` 计算，故控制频率变化时**速度上限保持不变**。
> **说明 2**：`max_tether` 是"影子点"（内部平滑后的目标点）与机体真实位置之间的水平误差上限，超过即被截断，用于防止影子点离机体过远。
> **说明 3**：上表为桥接包**默认参数**。启动时可用 `--ros-args -p max_step_intercept:=...` 覆盖；实际生效值请用 `ros2 param get /px4_bridge_drone_1 max_step_intercept` 核对。
> **说明 4（重要）**：速度上限还受 PX4 参数二次约束。当前 `px4-rc.params` 固化 `MPC_XY_VEL_MAX=14.0`，ATTACK 档的 12.4 m/s 可在该参数内达到；但更早实测的 `V_max = 23.59 m/s` 在当前参数下**不可复现**（详见 §4 注 1）。
> **说明 5（重要）**：`max_speed` 是**速度指令上限**，不等于实际跟踪速度。桥接控制律为 `v = min(max_speed, edist × gain_p) + 速度前馈`，其中 `edist` 为影子点到目标的距离。因此若上游规划给出的目标点只领先机体 0.74 m，INTERCEPT 档的 P 项仅 `1.8 × 0.74 ≈ 1.33 m/s`，实际跟踪速度会明显低于 7.6 m/s。**"实际跟踪速度"必须作为独立验收指标**，不能以档位配置值代替（联调中已出现"配置 7.6、实测 4~6"的偏差）。

#### 接口 I：云台协同指令
- **发送方**：系统集成节点
- **接收方**：飞控 DDS 桥接节点
- **Topic 名称**：`/drone_<id>/fmu/in/gimbal_setpoint`
- **消息类型**：`px4_msgs/msg/GimbalManagerSetPitchYaw`（暂定）
- **业务约定**：中枢根据视觉目标的像素偏差，在锁定模式下计算云台偏转角并下发。

### 2.4 传感器输入接口（底层至视觉）

本接口由飞控底层（或 Gazebo 仿真器）负责提供，视觉模块负责订阅，中枢节点不处理原始图像。此接口为全系统铁律。

#### 接口 J：相机原始图像（多机隔离）
- **发送方**：飞控 DDS 桥接节点 / Gazebo
- **接收方**：视觉节点
- **Topic 名称**：`/drone_<id>/camera/image_raw`（例如 `/drone_1/camera/image_raw`）
- **消息类型**：`sensor_msgs/msg/Image`
- **业务约定**：飞控同学必须确保仿真里的相机数据被桥接成了 ROS 2 原生标准消息，并且由于多机存在，必须使用带 `<id>` 的命名空间隔离，防止 3 架飞机的画面串流。
- **算力与融合约定**：视觉节点需同时订阅多路视频流，但运行单实例 YOLO。采用“主从切换策略”——只要任意一架无人机的画面捕获到目标，视觉节点即采用该飞机的内参计算全局 ENU 坐标，并发布至 `/vision/target_pose` 供中枢与规划共享。

#### 接口 K：相机内参
- **发送方**：飞控 DDS 桥接节点 / Gazebo
- **接收方**：视觉节点
- **Topic 名称**：`/drone_<id>/camera/camera_info`
- **消息类型**：`sensor_msgs/msg/CameraInfo`
- **业务约定**：视觉节点必须读取该消息获取焦距、主点等物理参数，用于将二维像素（2D）反投影计算为三维全局坐标（3D）。

## 3. 坐标系规范（全系统铁律）
- **内部算法坐标系**：全系统（规划、中枢、视觉、外部转换）统一使用 ROS 标准的 **ENU 坐标系**（东-北-天，Z轴向上为正，单位：米）。
- **飞控坐标系**：PX4 底层使用 NED（北-东-地）。
- **坐标转换职责**：由底层的飞控 DDS 桥接节点统一负责将中枢发出的 ENU 坐标转换为 NED。其他任何模块严禁加坐标系转换逻辑。

## 4. 动力学参数与预测边界
规划模块不需要关心底层飞控 PID 曲线，只需基于中枢提供的理论物理极限进行轨迹计算。

以下数值来自飞控桥接包的仿真实测（来源：`src/flight_ctrl_pkg/README.md` 第五节「机型动力学实测基准」，测量命令 `ros2 launch flight_ctrl_pkg dynamics_calibrator.launch.py step_dist:=20.0`）：

| 动力学指标 | 实测值 | 用途 / 适用档位 |
| :--- | :--- | :--- |
| **巡航速度** `V_cruise` | `4.50 m/s` | `TRACK` / `HOVER` / `RETURN` 稳态档；常规追踪与平滑轨迹规划 |
| **突防峰值速度** `V_max` | `23.59 m/s`（`84.9 km/h`） | `ATTACK` 档全速冲刺；拦截提前量计算（**见注 1，需复核**） |
| **最大水平加速度** `a_max` | `10.82 m/s²` | 刹车距离与「最早可达时间」计算 |
| **偏航转弯角速度** `ψ_max` | `185.2 deg/s` | 大机动转弯耗时、内圈卡位 |
| **末端最小交汇脱靶量** | `0.15 m` | 3v3 三维四面体钳形合围实测 |
| **集群最小安全间距** | `2.26 m` | 多机防撞约束（红线 > 1.2 m） |
| **停机坪触地复位精度** | `< 0.20 m` | 返航对准 `H1(0,0)` / `H2(0,3)` / `H3(0,6)` |
| **最小转弯半径** `R_min` | 待实测 | 暂无可靠标定值，可暂按 `R_min ≈ V² / a_max` 估算 |

> **注 1（待复核）**：`V_max = 23.59 m/s` 是在 PX4 `MPC_XY_VEL_MAX=26.0`、`MPC_TILTMAX_AIR=48.0°` 条件下测得的。当前 `flight_ctrl_pkg/scripts/px4-rc.params` 已固化为 `MPC_XY_VEL_MAX=14.0`、`MPC_TILTMAX_AIR=55.0°`，**横向速度上限为 14 m/s**，该峰值在当前参数下不可复现。规划模块在用它计算拦截提前量前，必须先确认当时生效的 `MPC_XY_VEL_MAX`；或由飞控侧在当前参数下重测后回填。

> **注 2**：中枢据此设定底层 `max_step` 限幅，桥接换算关系为「速度上限 = `max_step × 20Hz`」。各档位的具体数值见接口 H 与桥接包 README。

## 6. 机动性能验收指标

> **为什么需要这一节**：动作枚举里 `INTERCEPT` 写的是“解除常规限幅、全速切内圈卡位”，`ATTACK` 写的是“彻底解除限幅、全速冲刺”。“全速”没有数值，出现过**配置档位 7.6 m/s、实测只有 4~6 m/s** 的争议——双方都能说“按我的定义是对的”。本节把“全速”改成可测指标，并明确测量前提，避免把上游约束误判为桥接缺陷。

### 6.1 术语与测量前提

- **速度上限（配置值）**：`max_step × 20Hz`，见接口 H《限幅档位对照表》。这是桥接允许输出的速度指令上限。
- **实际跟踪速度**：`v = min(速度上限, edist × gain_p) + 速度前馈`。它受上游给出的**目标点超前量** `edist` 直接影响，因此**不等于**配置值。
- **测量前提（必须满足）**：测量时目标点相对机体的领先量应 **≥ 20 m**（或使用 `dynamics_calibrator.launch.py step_dist:=20.0` 的等效阶跃）。若上游把目标点钉在机体附近（例如只领先 0.74 m），P 项会被压到 `1.8 × 0.74 ≈ 1.33 m/s`，此时测到的是**上游约束**，不能判定桥接不达标。

### 6.2 速度指标

在满足 6.1 测量前提、且直线段无避障介入的情况下，各档位的**实际跟踪速度**应达到配置上限的 90%：

| 档位 | 配置速度上限 | 验收下限（90%） | 测量窗口 |
| :--- | ---: | ---: | :--- |
| 常规档（`TRACK`） | 2.8 m/s | **≥ 2.5 m/s** | 直线段稳定 3 s |
| `INTERCEPT` | 7.6 m/s | **≥ 6.8 m/s** | 直线段稳定 3 s |
| `ATTACK` | 12.4 m/s | **≥ 11.2 m/s** | 直线段稳定 2 s |

**测量方法**：发布一个距机体 ≥ 20 m 的固定目标点，待机体进入匀速段后，采样 `/drone_<id>/state` 的 `twist.twist.linear` 水平分量（`hypot(vx, vy)`），取稳定段均值。注意 `MPC_XY_VEL_MAX=14.0` 是 PX4 侧硬上限，ATTACK 档 12.4 m/s 在参数允许范围内。

### 6.3 交战指标

目标以匀速直线横穿（高度与机体同层或差 ≤ 2 m），记录我方与目标的**最小三维距离**：

| 目标速度 | 指标 | 说明 |
| ---: | :--- | :--- |
| 4 m/s | 最近距离 **< 0.5 m**（实测基准 `0.030 m`） | 应当稳定达成 |
| 6 m/s | 见 6.4 能力声明 | 当前不作为达标要求 |

**测量方法**：用真值位姿（或靶机驱动脚本）逐帧计算距离；由于 `/state` 为 20 Hz、末段速度高，**应按相邻两帧连线的点到线段距离取最小值**，不能只比较采样点，否则会把真实最近点算大。

### 6.4 当前目标速度上限（能力声明）

依据 2026-11 联调实测（`08_intercept4.log` / `09_intercept6.log`）：

| 目标速度区间 | 结论 | 实测依据 |
| :--- | :--- | :--- |
| **≤ 4 m/s** | **保证命中**（最近距离 < 0.5 m） | 4 m/s 横穿：最近 `0.030 m`，HIT |
| 4 ~ 6 m/s | **不保证**，属待提升区间 | 6 m/s 横穿：最近 `9.939 m`，MISS 且距离持续拉大 |
| > 6 m/s | 明确不支持 | — |

> 提升该上限需要两侧同时改进：**规划侧**给出足够的点超前量（当前 `apply_constraints` 把点裁到 `own + max_step`，全程只领先 0.74 m），**桥接侧**确认 P 项与前馈上限（当前 INTERCEPT `gain_p=1.8`、`max_tether=2.4`）是否需要在 INTERCEPT 档放宽。单改任一侧都不足以达到 7.6 m/s。

### 6.5 不达标时的归因次序

出现“实际跟踪速度低于验收下限”时，**按以下顺序排查**，避免互相甩锅：

1. **上游超前量**：`ros2 topic echo /planning/target_pose` 看目标点与 `/drone_<id>/state` 的距离，是否 ≥ 20 m（或至少 ≥ `max_tether`）。若被钉在机体附近 → 规划侧问题。
2. **档位参数是否真正生效**：`ros2 param get /px4_bridge_drone_1 max_step_intercept`，并确认中枢确实下发了 `/drone_<id>/action = "INTERCEPT"`。
3. **PX4 侧上限**：确认生效的 `MPC_XY_VEL_MAX`（当前固化 14.0），以及倾角限制 `MPC_TILTMAX_AIR`。
4. 前三项都正常仍不达标，才判定为桥接控制律问题（P 项 / 前馈上限需调整）。

## 补充  战术动作枚举（Action Enum）强制规范
为防止大小写混用或拼写错误导致中枢状态机解析失败，`action` 字段的字符串**必须严格**使用以下枚举值（全大写）：

各枚举值对应的飞控限幅数值（`max_step` / 速度上限 / `max_tether` / 加速度前馈上限等）统一见接口 H 的《限幅档位对照表》。

1. **`TAKEOFF`**：起飞。指令无人机解锁并升至指定安全高度。
2. **`HOVER`**：悬停。指令无人机在当前坐标原地保持不动。
3. **`RETURN`**：返航。指令无人机触发失控保护/自动返航，飞回起飞点。
4. **`TRACK`**：跟随。尚未辨明目标身份，保持常规限幅与安全距离跟飞。
5. **`INTERCEPT`**：追击。已辨明敌意，解除常规限幅，全速切内圈卡位。飞控桥接 INTERCEPT 档的实际限幅：**速度上限 7.6 m/s**（`max_step_intercept = 0.38` × 20Hz）、位置误差上限 `max_tether = 2.4 m`、比例增益 `gain_p = 1.8`、水平加速度前馈上限 `8.0 m/s²`、垂直速度上限 `3.8 / 4.0 m/s`（上/下）。
6. **`ATTACK`**：攻击。终极指令，彻底解除限幅，全速直线撞击目标。
7. **`RESUME_PATROL`**：恢复执行任务。具体内容待定。
