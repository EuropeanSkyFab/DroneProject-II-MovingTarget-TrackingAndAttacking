# P5 理论参数注入（学长数据）

2026-11-19 ｜ 用于 `.p5/main_ws` 工作区 ｜ 不改 main 的原始参数/代码，不合并 main

## 目的

把 main 的 `flight_ctrl_pkg` 桥接和 PX4 仿真参数，按学长桥接模块的理论基准注入：

| 参数 | 理论值 |
|---|---:|
| `V_cruise` / `v_max` | 4.50 m/s |
| `V_intercept` | 7.60 m/s |
| `V_max` / `v_max_attack` | 23.59 m/s |
| `a_max` | 10.82 m/s² |
| `yaw_rate_max` | 185.2 deg/s |
| `max_step_default` | 0.225 m/帧（20 Hz 等效 4.50） |
| `max_step_intercept` | 0.38 m/帧（7.60） |
| `max_step_attack` | 1.1795 m/帧（23.59） |
| PX4 `MPC_XY_VEL_MAX` | 26.0 |
| PX4 `MPC_TILTMAX_AIR` | 48.0 |
| PX4 `MPC_ACC_HOR_MAX` | 12.0 |
| PX4 `MPC_XY_CRUISE` | 4.5 |
| PX4 `MPC_YAWRAUTO_MAX` | 185.2 |

这些是**理论参考值，不是本机实测**。P5 在 Gazebo `x500_down_cam` 上实测只有 `V_max=13.00`、`a_max=10.13`、`yaw=168.6`，真实无人机结构未知。

## 注入文件

- `src/flight_ctrl_pkg/scripts/px4-rc.theory.params`：学长理论 PX4 参数表，保留 main 原表的安全/云台/电池项。
- `src/flight_ctrl_pkg/scripts/start_px4_theory.sh`：读取上表的启动脚本，不读 main 的 `px4-rc.params`。
- `theory_bridge_params.yaml`：`flight_ctrl_pkg` 桥接的 ROS 参数，`max_step_*` 为三档理论值。
- `run_p5_theory.sh`：一键拉起 PX4 + Gazebo + MicroXRCEAgent + 桥接 + 算法 + 中枢。

main 的原始 `px4-rc.params`、`flight_ctrl_single.launch.py`、桥接代码都没有改。

## 验证理论值有没有真的生效

先看桥接和 PX4 的状态：

```bash
source /opt/ros/humble/setup.bash
source .p5/main_ws/install/setup.bash
export ROS_DOMAIN_ID=0
ros2 topic info /fmu/out/vehicle_status_v1
ros2 topic echo /drone_1/state --once
```

再跑动力学标定：

```bash
ros2 launch flight_ctrl_pkg dynamics_calibrator.launch.py step_dist:=20.0
```

判定：

- 如果 `V_max` 接近 23.59、`a_max` 接近 10.82、`yaw` 接近 185.2，说明注入生效，学长理论值在这套模型上复现。
- 如果还是 13.00 左右，说明 main 的仿真/桥接还在限速：重点查 `MPC_XY_VEL_MAX` 是否真的被 PX4 接受，以及桥接 `max_step_attack=1.1795` 是否生效。
- 不管结果如何，先记录实际值，再决定是否改 main。

## 注意

- 这是 `.p5/main_ws` 里的本地覆盖，不提交、不合并；如果 main 以后更新，需要重新套一遍。
- 算法 `algorithm_pkg` 的 launch 也已按同一套理论值改；但算法侧 `max_step` 仍是单值，桥接侧是三档。冲突三、四要按新参数重跑，不能沿用旧 6.0 / 0.30 的数据。
- 理论值不是真机实测；真机/机型确认后还要重新标定。


## 首次验证结果（2026-11-19）

用 `run_p5_theory.sh` 在干净容器里跑通，桥接注入生效：

- `gimbal=False`，`max_yaw_rate_deg=185.2`，说明 `theory_bridge_params.yaml` 被桥接读到了。
- `dynamics_calibrator step_dist:=20.0` 实测：V_cruise 5.52、V_max 14.65、a_max 9.67、yaw 185.2、R_min 3.15。

没有达到学长理论的 V_max=23.59：

- 14.65 更接近 main 的 `px4-rc.params` 里 `MPC_XY_VEL_MAX=14.0`，不是理论文件里的 26.0。
- 说明 `px4-rc.theory.params` 里的 `MPC_XY_VEL_MAX=26` 没有被 PX4 真正接受，或者 `PX4_PARAM_*`/`PX4_RC_PARAMS_POST` 注入路径没有生效。
- 这就是 main 的数据冲突：README 写 26/23.59，实际参数表写 14.0，桥接 `max_step` 又是 12.4 档，三者对不上。

结论：桥接层注入可用；PX4 层还没被理论值覆盖。P5 的冲突二、三、四还不能按 23.59 收口，先要修 main 的 PX4 参数注入，或明确接受当前仿真的 14.65 m/s 上限。


## 运行时注入后的复测（2026-11-20）

PX4 参数确认 set 成功（26/48/12/4.5/185.2 全部读回一致），桥接 `max_step_attack=1.1795` 也确认生效，但动力学标定仍是：

| 模型 | V_cruise | V_max | a_max | yaw | R_min |
|---|---:|---:|---:|---:|---:|
| `x500_down_cam` | 5.45 | 14.69 | 9.79 | 172.4 | 3.03 |
| `x500`（无相机） | 5.52 | 14.82 | 9.88 | 174.2 | 3.09 |

结论：**V_max 卡在 14.8 左右，不是 PX4 参数没注入**。PX4 参数已经是 26，桥接也是 1.1795，但模型/控制器只能在 48° 倾角下跑到 14.8；`x500` 和 `x500_down_cam` 都一样。学长 23.59 是另一套模型/控制器/桥接条件下的理论值，不是这套 main 仿真能达到的值。

P5 到此收口：算法侧参数已按理论值注入，运行时注入也验证了；但 main 的仿真上限 14.8，不能声称 23.59 在本仿真通过。
