# 代码注释规范

本文约定 `algorithm_pkg` 的注释写法。注释的目标是让读者在不询问作者的情况下理解以下内容，而不是要求每行都有注释：

- 函数的整体功能；
- 参数、返回值和异常；
- 具体代码段的作用；
- 容易出错的位置、接口不完善的位置，以及尚未完成的部分。

---

## 1. 三层注释

### 1.1 模块 docstring

文件开头用一段 docstring 说明模块职责、运行环境和关键假设。

```python
"""规划算法纯函数核心：目标预测、拦截求解、安全约束。

本模块刻意不依赖 ROS，便于在宿主机和 Humble 容器里直接跑 pytest。

P1 假设：
- 目标做匀速直线运动（CV 模型）。
- 己方可以在任意方向以 v_max 飞行，暂不考虑加速度和转弯半径。
- 位置、速度都使用右手 ENU 坐标系，单位米 / 米每秒。
"""
```

### 1.2 函数 / 类 docstring

使用 Google 风格，配合 VS Code 的 autoDocstring 插件生成骨架。

```python
def predict_target(samples, now, *, max_age=1.0, max_speed=15.0):
    """根据最近的目标位置采样，估计 now 时刻的位置和速度。

    Args:
        samples: 目标位置采样序列；顺序可以乱，函数内部会排序。
        now: 当前时刻，单位秒；必须和 samples 使用同一个时钟。
        max_age: 允许的最大数据年龄，单位秒；超过后 valid=False。
        max_speed: 允许的最大目标速度，单位米/秒；超过则返回 None。

    Returns:
        估计出的 TargetState；没有可用采样或速度超限时返回 None。

    Raises:
        ValueError: max_age 为负数，或 max_speed 不是正数。

    Note:
        返回 valid=False 时仍然会返回状态，方便记录日志；
        但调用方不应再基于它规划。
    """
```

常用 section：

| section | 用途 |
| --- | --- |
| 第一行 | 说明函数功能 |
| `Args:` | 每个参数的含义、单位、取值 |
| `Returns:` | 返回什么；`None` 表示什么 |
| `Raises:` | 什么情况下抛异常 |
| `Note:` | 重要边界、调用约定、已知限制 |

### 1.3 行内注释

行内注释解释“这一段具体在做什么”或“为什么这样做”，不逐行翻译语法。

```python
# 把 x、y 限制在 ±max_xy，把 z 限制在 [z_min, max_alt]。
# 例如 max_xy=1000 时，x=2000 会变成 1000。
x = _clamp(point[0], -max_xy, max_xy)
y = _clamp(point[1], -max_xy, max_xy)
z = _clamp(point[2], z_min, max_alt)
```

## 2. autoDocstring 的使用方式

autoDocstring 是函数 docstring 生成工具，不用于生成行内注释。

一般用法：

1. 在函数签名下一行输入 `"""`，按回车；
2. 插件根据函数签名生成 `Args`、`Returns`、`Raises` 骨架；
3. 补充每个参数的中文说明、单位和边界；
4. 修改函数签名后，重新生成或手动补齐 docstring。

推荐设置：

```json
{
  "autoDocstring.docstringFormat": "google",
  "autoDocstring.startOnNewLine": false
}
```

说明：

- `google` 格式和本文示例一致；
- 类型已经写在函数签名里，`Args` 里不必重复类型，写“含义 + 单位 + 取值”即可；
- docstring 是“函数契约”，行内注释是“实现说明”，两者不要互相替代。

参考：

- [autoDocstring GitHub](https://github.com/NilsJPWerner/autoDocstring)
- [autoDocstring Marketplace](https://marketplace.visualstudio.com/items?itemName=njpwerner.autodocstring)

## 3. Better Comments 标签规范

可以继续用 `# !`、`# ?`、`# TODO:`、`# *`，但只能标“关键位置”，不能拿来当段落标题或逐行装饰。

| 标签 | 使用场景 | 禁止用法 |
| --- | --- | --- |
| `# !` | 接口不完善、容易静默失败、安全边界、必须二次处理的位置 | 不要给普通赋值、普通 `if` 加 |
| `# ?` | 设计原因不明显，读者会问“为什么这里要这样” | 不要解释一眼能看懂的代码 |
| `# TODO:` | 已知未完成、需要后续阶段补的工作 | 不要写没有具体动作的后续说明 |
| `# *` | 一段主流程的起点，需要快速定位 | 不要当小标题，不要每个函数都用 |
| `# //` | 已废弃、不应沿用的旧逻辑 | 新代码中尽量不用 |

数量建议：

- 一个函数最多 1～3 个关键位置；同一个位置可以写 1～2 行标签注释；
- 普通行内注释也不求多，只写“代码本身看不出来的信息”；
- 同一个意思不要在 docstring 和行内注释里重复两遍。

## 4. 写作规则

### 4.1 先写“做什么”，再写“为什么”

不推荐：

```python
# 先做绝对边界裁剪
x = _clamp(point[0], -max_xy, max_xy)
```

推荐：

```python
# 把 x、y 限制在 ±max_xy，把 z 限制在 [z_min, max_alt]。
# 例如 max_xy=1000 时，x=2000 会变成 1000。
x = _clamp(point[0], -max_xy, max_xy)
y = _clamp(point[1], -max_xy, max_xy)
z = _clamp(point[2], z_min, max_alt)
```

### 4.2 写具体数字、单位、条件

不推荐：

```python
# 高度做一下保护
z_min = min_alt if action == "ATTACK" else max(min_alt, safe_alt)
```

推荐：

```python
# ? ATTACK 可能打低空目标，最低高度用 min_alt=3 米。
# ? TRACK/INTERCEPT 用 safe_alt=5 米，防止撞地和下洗气流。
z_min = min_alt if action == "ATTACK" else max(min_alt, safe_alt)
```

### 4.3 不写无信息量的注释

不推荐：

```python
# 如果 action 不在列表里就返回 None
if action not in ("TRACK", "INTERCEPT", "ATTACK"):
    return None
```

推荐：

```python
# ! TAKEOFF/HOVER/RETURN 的点由中枢生成。
# ! 这里返回 None，避免规划和中枢同时控制。
if action not in ("TRACK", "INTERCEPT", "ATTACK"):
    return None
```

### 4.4 注释和代码必须同步

- 改函数签名，必须改 docstring；
- 改边界值，必须改注释里的数字；
- 注释和代码冲突时，以代码为准，并立即修注释；
- 不要把“临时调试注释”提交进仓库。

## 5. 例子

### 例子 1：函数 docstring

不推荐：

```python
def apply_constraints(point, mode, *, own=None, max_step=None):
    """裁剪规划点。"""
    ...
```

问题：读者不知道裁什么、为什么裁、返回 `None` 是什么意思。

推荐：

```python
def apply_constraints(
    point: Optional[Vec3],
    mode: str,
    *,
    own: Optional[Vec3] = None,
    min_alt: float = 3.0,
    safe_alt: float = 5.0,
    max_alt: float = 50.0,
    max_xy: float = 1000.0,
    max_step: Optional[float] = None,
) -> Optional[Vec3]:
    """把规划点裁剪到当前飞行安全包线内。

    这是纯函数：不修改传入的 point，返回一个新的 (x, y, z)。
    只处理 TRACK/INTERCEPT/ATTACK；其他模式返回 None，因为
    TAKEOFF/HOVER/RETURN 的坐标由中枢生成。

    Args:
        point: 待裁剪的 ENU 点，单位米；None 表示本帧没有点。
        mode: 当前战术模式，大小写不敏感。
        own: 己方当前位置；只有同时给 max_step 时才限制步长。
        min_alt: ATTACK 的最低高度，默认 3 米。
        safe_alt: TRACK/INTERCEPT 的最低高度，默认 5 米。
        max_alt: 最高高度，默认 50 米。
        max_xy: 水平边界，x/y 限制在 ±max_xy，默认 1000 米。
        max_step: 每个控制周期允许的最大位移，单位米；None 表示不限。

    Returns:
        裁剪后的 (x, y, z)；无法或不应发布时返回 None。

    Raises:
        ValueError: 高度/边界参数矛盾，或 max_step 不是正数。

    Note:
        中枢的 plan_callback 只接受 z ∈ [3, 50]；这里先裁。
        max_step 是设定值跳变限制，不是刹车距离。
    """
```

### 例子 2：普通行内注释

不推荐：

```python
# 处理一下
if length > max_step:
    scale = max_step / length
    clamped = (
        own[0] + step[0] * scale,
        own[1] + step[1] * scale,
        own[2] + step[2] * scale,
    )
```

推荐：

```python
# 如果这一帧要飞的距离超过 max_step，
# 就把向量按比例缩短到 max_step。
# 例如 length=20、max_step=2 时，scale=0.1。
if length > max_step:
    scale = max_step / length
    clamped = (
        own[0] + step[0] * scale,
        own[1] + step[1] * scale,
        own[2] + step[2] * scale,
    )
```

### 例子 3：特殊标签只标注关键位置

```python
# ! A≈0：目标速度和己方极限速度相同，二次方程退化成一次方程。
# ! 直接除以 A 会除零，必须单独分支。
if abs(a) <= _EPS:
    if abs(b) > _EPS:
        t_linear = -c / b
        if _EPS < t_linear <= t_go_max + _EPS:
            candidates.append(t_linear)
else:
    discriminant = b * b - 4.0 * a * c

    # ? 判别式在 0 附近会被浮点误差算成 -1e-16。
    # ? 用 -_EPS 容差，避免把“刚好相切”误判成不可达。
    if discriminant >= -_EPS:
        ...
```

这里 `# !` 标注容易出错的位置（除零），`# ?` 说明需要容差的原因，不是为普通 `if` 添加装饰。

### 例子 4：数学密集块

数学块不能只写“做拟合”，要交代：公式在算什么、单位是什么、什么条件下会退化、返回值为什么可能不可信。

```python
# t_ref 是最新采样时刻。用相对时间做拟合，
# 避免大时间戳相减时损失浮点精度。
t_ref = latest.stamp
times = [sample.stamp - t_ref for sample in clean]

# denominator 是最小二乘斜率公式的分母，单位是秒²。
# 它同时用来判断时间跨度是否足够。
denominator = sum((t - mean_t) ** 2 for t in times)

if denominator <= _EPS:
    # 时间跨度太小时斜率不可信：
    # 位置取最新采样，速度置 0，并标记 velocity_valid=False。
    velocity_valid = False
else:
    # slope 是速度分量，单位 m/s；
    # intercept 是最新时刻的拟合位置，单位米，不是拦截点。
    ...
```

要点：

- 写“为什么用相对时间”，不要只写“减去 t_ref”；
- 写清 `denominator` 的单位和阈值含义；
- `velocity_valid=False` 不是“目标静止”，而是“速度估不出来”；
- `intercept` 容易和“拦截点”混淆，必须说明它只是拟合截距。
