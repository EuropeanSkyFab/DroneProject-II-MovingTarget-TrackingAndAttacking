# 算法部分：原理与策略（P1）

> 一句话：算法只做一件事——根据目标现在在哪、往哪飞，算出**己方无人机下一步该去哪个点**，并说明当前是跟踪、拦截还是攻击。

本文是 P1 纯算法层的说明。它不依赖 ROS，不直接控制飞机，也不负责避障、限幅和状态机。

---

## 1. 算法在系统里的位置

```text
视觉 / 外部目标位置 ──┐
                      ├──> 规划算法 ──> 一个 ENU 点 + action
己方无人机状态 ───────┤
课题三战术指令 ───────┘
```

规划算法拿到三样东西：

1. **目标位置**：来自视觉或外部目标，只有位置，没有速度；
2. **己方状态**：当前位置，用来算距离和方向；
3. **战术指令**：`TRACK`、`INTERCEPT`、`ATTACK`。

输出只有两样：

- 一个三维点 `(x, y, z)`，单位米，ENU 坐标系；
- 一个 `action` 标签，说明这个点是跟踪点、拦截点还是攻击点。

真正的避障、限幅、状态切换在中枢和飞控桥接里，规划算法不越界。

---

## 2. 三种战术，先用人话理解

| 模式 | 一句话 | 打法 | 速度 | 追不上怎么办 |
| --- | --- | --- | --- | --- |
| `TRACK` | “我看着你，保持距离” | 跟住目标，不贴脸 | `V_cruise`（约 3 m/s） | 继续跟预测点 |
| `INTERCEPT` | “我抢到你前面” | 算目标未来位置，提前占位 | `V_max`（约 6 m/s） | 退化为尾随点 |
| `ATTACK` | “不绕了，撞上去” | 直线冲向未来撞击点 | `V_max` | 不尾随，输出无效 |

三种模式是**意图递增**：跟踪 → 拦截 → 攻击。

### 2.1 TRACK：跟随

目标身份还没确认，或者还没到攻击时机。要做的是：

- 保持能看到目标；
- 保持安全距离，不贴脸；
- 目标机动时能跟上。

P1 的约定：

> **TRACK 模式下，规划只发目标的预测位置，不做 standoff 偏移。**

原因是中枢的 TRACK 分支在距离小于 5 米时已经会自己做环绕偏移。如果规划再减一次 `d_safe`，就会双重偏移，点会跑到奇怪的位置。

### 2.2 INTERCEPT：抢位

已确认敌意，要抢到目标前方或内侧，卡住它的路线。不是撞，是占位。

核心不是追目标“现在”的位置，而是追目标“未来会到”的位置。就像守门员出击：不是追球，而是预判球会到哪，提前跑过去。

### 2.3 ATTACK：撞击

终极指令，不再绕行，直线全速撞向目标未来位置。

ATTACK 和 INTERCEPT 用同一个拦截方程，但降级策略不同：

- INTERCEPT 追不上，可以退化为尾随点；
- ATTACK 追不上，**不能**默默发尾随点。否则中枢会按 ATTACK 全速飞向目标后方，动作和意图完全错位。

P1 的选择是：**ATTACK 无解时返回“无点”**，由上层决定保持、降级还是清空。

## 3. 目标预测：先估速度，再推位置

### 3.1 为什么不能直接追当前位置

目标在动。你追它上一帧的位置，永远慢半拍。所以要先估计它的速度，再推它未来会到哪。

### 3.2 怎么估速度

输入是一串带时间戳的位置点：

```text
(t0, p0), (t1, p1), (t2, p2), ...
```

P1 用最简单的**匀速直线模型（CV）**：

- 对 x、y、z 三个方向分别做一次最小二乘直线拟合；
- 直线的斜率就是速度；
- 把直线外推到当前时刻，就是预测位置。

只有一帧位置，或参与拟合的帧时间跨度太小时，速度设为 0，并标记 `velocity_valid=False`。这不是“目标静止”，只是“还估不出速度”。

### 3.3 代码里的最小二乘

`predict_target()` 用相对时间做拟合，原因是直接拿 `stamp` 算 `t - mean_t` 会有大数相减的精度损失：

```python
t_ref = latest.stamp
times = [sample.stamp - t_ref for sample in clean]
```

`denominator = Σ(t - mean_t)²` 是斜率公式的分母，单位是秒²。它同时承担“时间跨度是否足够”的判断：

- `denominator <= 1e-9`：两帧时间戳几乎重合，斜率不可信。此时位置取最新采样，速度置 0，并令 `velocity_valid=False`；
- 否则：x/y/z 各拟合一条直线，斜率是速度分量，截距是最新时刻的拟合位置。

最后用 `position_at_ref + velocity * age` 外推到 `now`。拟合和外推分开，是为了让 `position` 和 `velocity` 都对应同一个参考时刻，避免“位置是旧的、速度是新的”。

### 3.4 预测什么时候失效

两个条件：

1. **太旧**：`now - 最新采样时间 > max_age`（默认 1 秒），标记 `valid=False`；
2. **速度太离谱**：估计速度超过 `max_speed`（默认 15 m/s），直接丢弃，避免把检测跳变当成目标高速运动。

预测失效时，规划不应该再输出点。

## 4. 拦截点：一个二次方程

### 4.1 问题

目标从 `p_t` 出发，以速度 `v_t` 匀速飞。己方在 `p_o`，最大速度 `v_max`。问：

> 多长时间后，己方能到达目标那时所在的位置？

目标未来位置：

```text
p_t(t) = p_t + v_t * t
```

己方 `t` 秒能飞到的范围是一个半径 `v_max * t` 的球面。要碰上：

```text
|p_t + v_t * t - p_o| = v_max * t
```

两边平方，整理成二次方程：

```text
A * t² + B * t + C = 0

A = |v_t|² - v_max²
B = 2 * (p_t - p_o) · v_t
C = |p_t - p_o|²
```

解出正根 `t_go`，拦截点就是：

```text
p_intercept = p_t + v_t * t_go
```

### 4.2 三个必须处理的边界

**（1）`A = 0`：目标速度和己方极限速度一样**

二次方程退化成一次方程：

```text
B * t + C = 0
```

不能直接除以 `A`，要单独分支。

**（2）没有正根：追不上**

不是所有目标都能拦。目标更快时，也不一定追不上：

- 迎头飞来，即使目标更快，也可能拦得住；
- 同向远离且更快，通常追不上；
- **快速横穿，也可能无解**。

所以不要用“目标更快”或“同向/迎头”做前置判断。正确做法只有一个：

> 解方程，看有没有落在 `(0, t_go_max]` 里的正根。

**（3）`t_go` 太大：没有工程意义**

匀速模型外推几十秒没有意义。P1 默认 `t_go_max = 8 秒`，超过就当作不可达。

### 4.3 追不上时的尾随点

INTERCEPT 无解时，输出尾随点：

```text
p_tail = p_t - unit(v_t) * d_tail
```

也就是卡在目标运动轨迹后方 `d_tail` 米处。目标一旦转弯或减速，下一帧可能就变成可达。

如果目标速度接近 0，尾随点直接取目标位置。

## 5. 安全约束：点算出来，还要能飞

### 5.1 高度

| 模式 | 最低高度 | 原因 |
| --- | --- | --- |
| `TRACK` / `INTERCEPT` | `H_safe = 5 m` | 防撞地、防下洗气流 |
| `ATTACK` | `MIN_ALT = 3 m` | 目标可能只有 3～5 米高，抬到 5 米就打不中 |

上限统一 `MAX_ALT = 50 m`。中枢的 `plan_callback` 只接受 `z ∈ [3, 50]`，规划侧先保证，避免消息被静默丢弃。

### 5.2 水平边界

`x`、`y` 限制在 `±1000 m` 内，对应中枢的 `MAX_XY_DIST`。

### 5.3 每周期最大跳变

`max_step` 是每个控制周期允许的设定值跳变量。它和“刹车距离”不是一回事：

- `d_brake = v² / (2 * a_max)`：什么时候该减速；
- `max_step`：每个周期允许跳多少米。

P1 的 `max_step` 先按 `v_max * dt` 给初值，再由联调标定。

## 6. 算法核心与 ROS 适配

纯算法在 `src/algorithm_pkg/algorithm_pkg/algorithm_core.py`，不依赖 ROS；
ROS 消息、参数、定时器和话题在 `algorithm_node.py`。两者分开，保证算法单测
不需要起 ROS，也方便在 Humble 容器里快速跑。

### 6.1 `predict_target`

```python
predict_target(samples, now, *, max_age=1.0, max_speed=15.0) -> TargetState | None
```

输入一串 `TargetSample`，输出当前时刻的目标状态：

```python
from algorithm_pkg.algorithm_core import TargetSample, predict_target

samples = [
    TargetSample(0.0, 0.0, 0.0, 10.0),
    TargetSample(1.0, 1.0, 0.0, 10.0),
    TargetSample(2.0, 2.0, 0.0, 10.0),
]

state = predict_target(samples, now=3.0)
# state.position ≈ (3.0, 0.0, 10.0)
# state.velocity ≈ (1.0, 0.0, 0.0)
# state.valid is True
```

返回 `None` 的情况：

- 没有可用采样；
- 数据里有 NaN/Inf；
- 估计速度超过 `max_speed`。

`valid=False` 表示目标太旧，不应该再规划。

`velocity_valid=False` 表示速度是占位值（只有一帧，或时间跨度太小），不能当成“目标静止”的结论。

### 6.2 `solve_intercept`

```python
solve_intercept(own, target, v_max, *, mode="INTERCEPT",
                t_go_max=8.0, min_distance=0.5, d_tail=4.0) -> InterceptSolution
```

输入己方位置、目标状态、最大速度，输出：

```python
from algorithm_pkg.algorithm_core import solve_intercept

result = solve_intercept(
    own=(0.0, 0.0, 10.0),
    target=state,
    v_max=6.0,
    mode="INTERCEPT",
)

if result.point is not None:
    print(result.point, result.t_go, result.reason)
```

`InterceptSolution` 的字段：

| 字段 | 含义 |
| --- | --- |
| `action` | `TRACK` / `INTERCEPT` / `ATTACK` |
| `point` | 输出点；`None` 表示这一帧不要发点 |
| `reachable` | 是否真正解出了拦截点 |
| `t_go` | 预计到达时间；尾随/跟踪时为 `None` |
| `reason` | 调试原因，例如 `intercept_point`、`fallback_tail`、`attack_no_solution` |

各模式行为：

- `TRACK`：返回目标预测点，不加偏移；
- `INTERCEPT`：有解返回拦截点；无解返回尾随点，`reachable=False`；
- `ATTACK`：有解返回拦截点；无解返回 `point=None`，绝不返回尾随点。

### 6.3 `apply_constraints`

```python
apply_constraints(point, mode, *, own=None,
                  min_alt=3.0, safe_alt=5.0, max_alt=50.0,
                  max_xy=1000.0, max_step=None) -> Vec3 | None
```

做三件事：

1. 按模式限制高度：ATTACK 最低 3 米，TRACK/INTERCEPT 最低 5 米；
2. 限制 `x/y` 在 `±1000` 米；
3. 如果传入 `own` 和 `max_step`，限制每周期跳变量。

```python
from algorithm_pkg.algorithm_core import apply_constraints

safe_point = apply_constraints(
    result.point,
    result.action,
    own=(0.0, 0.0, 10.0),
    max_step=0.3,
)

if safe_point is None:
    # 不发布点，交给中枢保持/降级
    ...
```

`TAKEOFF`、`HOVER`、`RETURN` 等模式返回 `None`：这些点由中枢生成，规划不抢控制。

### 6.4 ROS 2 适配节点

`algorithm_node.py` 把上面的纯函数接到课题二现有话题。完整的 ROS 参数表见该文件模块 docstring 的“ROS 参数说明”，包括每个参数的单位、默认值、作用，以及 `max_age` 与 `max_pred_age`、`target_timeout` 的区别。

订阅：

- `/vision/target_pose`（`PoseStamped`）：视觉目标，优先；
- `/external/target_detected`（`PoseStamped`）：外部检测，视觉不新鲜时兜底；
- `/strategy/cmd`（`String` JSON）：`drone_id` + `action`；
- `/drone_<id>/state`（`Odometry`）：己方 ENU 位置。

发布：

- `/planning/target_pose`（`String` JSON）：
  `{"drone_id", "stamp", "x", "y", "z", "action"}`。

行为：

- 只对 `TRACK/INTERCEPT/ATTACK` 发点；具体判断由 P2 的
  `plan_policy.plan()` 完成，节点只负责把结果变成 JSON；
- `TRACK` 只发目标预测点，不做 standoff；
- `INTERCEPT` 不可达时发尾随点；`ATTACK` 不可达时 P2 不发点，
  适配层改发“当前位置保持点”，避免中枢继续使用旧攻击点；
- `INTERCEPT/ATTACK` 至少两帧目标、`velocity_valid=True`，且预测年龄
  不超过 `max_pred_age`（默认 0.5s）才发点；
- `INTERCEPT`/`ATTACK` 分别使用 `v_max_intercept`/`v_max_attack`（默认 7.6/12.4 m/s），`v_max` 只作兜底；
- `/{drone_id}/state` 的新鲜度优先看 `header.stamp`，避免 center 转发旧帧造成“状态一直新鲜”；
- `stamp` 是发布时刻的 ROS 时钟秒数，不是目标消息时间；
- 高度、XY 边界与中枢 `plan_callback` 保持一致。

启动：

```bash
ros2 launch algorithm_pkg algorithm.launch.py
```

没有收到 `/strategy/cmd` 时默认 `HOVER`，不会主动发点；如果节点启动晚了，
重新发一次战术指令即可。

## 7. 一帧完整流程

```text
1. 收到目标位置采样
2. predict_target(samples, now)              -> 目标状态
3. plan(action, own, state, params)          -> PlanResult
4. 只有 result.point 不为 None 才发布
```

伪代码：

```python
state = predict_target(samples, now)
result = plan(action, own, state, plan_params)

if result.point is None:
    # P2 明确说明“为什么本帧不发点”
    return None

publish(result.action, result.point, stamp=now)
```

## 8. 什么时候输出“无点”

以下情况 P2 返回 `point=None`，不要发 NaN、Inf 或旧点：

- 没有目标采样（`target_missing`）；
- 目标预测过期（`target_invalid`）；
- 预测年龄超过 `max_pred_age`（`target_too_old`）；
- 己方位置缺失或含非有限值（`own_invalid`）；
- INTERCEPT/ATTACK 速度未估出（`velocity_unavailable`）；
- 目标距离小于 `min_distance`（默认 0.5 米），太近，避免撞；
- ATTACK 无解（`attack_no_solution`）；
- 未知动作、TAKEOFF/HOVER/RETURN、RESUME_PATROL；
- 安全边界裁剪后仍无有效点。

注意：

> “无点”不是“立即停机”。当前中枢会把上一帧规划点保留最多 2 秒；
> P2 纯函数仍返回“不发点”，适配层在 ATTACK 无解/目标失效时发
> 当前位置保持点作为兜底。若以后中枢支持显式清空，可替换这个兜底。

## 9. P1 的边界

P1 已经做的：

- 匀速目标预测；
- 拦截二次方程及边界；
- INTERCEPT 尾随降级；
- ATTACK 不尾随；
- 按模式区分高度；
- 纯 Python 单测；
- ROS 2 适配节点、launch、话题收发（`algorithm_node.py`）。

P1 暂不做的：

- 加速度、转弯半径约束；
- 多机攻击分配；
- 目标丢失后的复杂降级；
- 中枢 E/F 同名自回灌的修复；
- 云台/视觉控制。

这些属于 P2 的后续细化或 P4 联调阶段，不要塞进纯算法层。
