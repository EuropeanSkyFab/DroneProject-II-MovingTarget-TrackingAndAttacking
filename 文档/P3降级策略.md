# P3 异常降级与安全约束（纯 Python 层）

> 一句话：在 P1 几何/P2 策略之上，先判断“这一帧输入还能不能用”，再决定
> 是正常发点、外推、保持还是不出点，并且对最终输出再做一次安全裁剪。

本文是 P3 的降级策略表与边界说明，**不修改** `P2模式策略契约.md`
的七动作语义；两篇文档并列：P2 管“正常输入下发什么点”，P3 管
“输入异常时降级到什么级别、还能不能发点”。

---

## 1. P3 做什么 / 不做什么

P3 只做纯算法层的四件事：

1. **异常检测**（`validators.py`）：目标、己方状态、指令 JSON 分类；
2. **降级状态机**（`degrade_fsm.py`）：L0/L1/L2/L3 与滞回、恢复；
3. **分级降级输出**（`degrade_policy.py`）：按级别决定发什么点；
4. **安全护栏**（`safety_guard.py`）：发点前按固定顺序裁剪/拒绝。

P3 明确不做：

- 不写 ROS 节点、不 import rclpy、不订阅/发布、不打 ROS 日志；
- 不改中枢 `/strategy/cmd` 逻辑和 `plan_callback`；
- 不把 `/planning/target_pose` 里的 `action` 当成中枢控制输入；
- 不处理 E/F 同名话题自回灌（只在第 10.1 节记录为已知问题）；
- 不做 P4 的接口核对、mock 闭环、三机隔离、Humble colcon 联调；
- 不重新设计 P2 的七动作契约。

一帧数据流：

```text
目标 / 己方状态 / 指令 JSON
        │
        ▼
validate_target / validate_ego / validate_cmd      # 分类，不做决策
        │
        ▼
DegradeFSM.update(target_status, ego_status, now)  # L0/L1/L2/L3 + 滞回
        │
        ▼
plan_with_degrade(...)                             # 按级别决定发什么点
        │
        ▼
apply_safety_guard(...)                            # 固定顺序裁剪 + stamp
        │
        ▼
PlanResult(level, anomaly, point, reason, guard_notes, output_stamp)
```

## 2. 四级降级表

| 级别 | 触发 | 输出 | 战术含义 |
| --- | --- | --- | --- |
| L0 `NORMAL` | 输入新鲜合法 | P2 正常点 | 正常追击 |
| L1 `EXTRAPOLATING` | 目标短暂丢失，`age <= t_extrap_max` | CV 外推点，仍走 P2 动作语义 | 目标可能被遮挡，继续追 |
| L2 `HOLDING` | 外推超时，但己方状态正常 | 保持点（上一有效点或己方当前位置） | 目标真丢了，原地等 |
| L3 `NO_PLAN` | 己方断流、目标非法/越界、无法降级 | `point=None`，`reason=no_plan_*` | 规划失效，中枢接管 |
| 恢复 | 异常消失 | 先回 HOLDING 确认，再回 NORMAL | 不抖、不跳 |

`L1/L2` **不是** no_plan：它们仍然输出“有策略的降级点”。只有 L3 才
`point=None`。

> 注意：L1/L2 输出保持点时，`action` 仍保留中枢下发的 `TRACK/INTERCEPT/
> ATTACK` 标签，但 `reason` 明确写 `hold_*`。这不是伪造拦截点，也不是
> ATTACK 尾随点；适配层可用 `reason` 区分。

## 3. 状态迁移与滞回

```text
                连续 n_enter 帧异常（目标过期）
   NORMAL ────────────────────────────────► EXTRAPOLATING
     ▲  │                                          │
     │  │ 连续 n_enter 帧异常（过期超 t_extrap_max） │ age > t_extrap_max
     │  └───────────────────────────────► HOLDING ◄┘
     │                                          │
     │                                          │ 己方断流 / 目标非法
     │                                          ▼
     │ 连续 n_recover 帧有效                 NO_PLAN
     └──────────────────────────────────────  （L1/L2 也可直接进 L3）
              NORMAL ◄── HOLDING ◄── NO_PLAN
                        连续 n_exit 帧有效
```

规则：

- 进入更差级别需要连续 `n_enter` 帧异常；单帧抖动不改变级别。
- `EXTRAPOLATING` 有硬上限 `t_extrap_max`，超时立刻进 `HOLDING`。
- 异常消失后**不能直接跳 NORMAL**：
  - L1 → HOLDING（确认态）；
  - HOLDING 连续 `n_recover` 帧有效 → NORMAL；
  - NO_PLAN 连续 `n_exit` 帧有效 → HOLDING，再按 `n_recover` 回 NORMAL。
- `n_enter` 帧窗口内级别仍是 NORMAL；如果这期间目标年龄已经超过
  `max_pred_age`，P2 自身会不发点。这是滞回窗口内的正常现象，不是
  P3 输出抖动。
- **时间戳倒退的帧**：目标或己方任一方 `TIME_REVERSED`，本帧直接丢弃，
  不参与任何计数、不改变级别。倒退帧不出点，避免用坏时间戳污染输出。
- 己方异常优先于目标异常：没有己方位置时，不会因为目标还新鲜就继续算
  拦截点。

## 4. 异常检测与降级策略表

| 异常 | 检测 | 降级级别 | 输出 | 恢复条件 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 目标丢失 `< t_extrap_max` | `validate_target` 标 `STALE`/`MISSING`，FSM 算丢失时长 | L1 | CV 外推点，仍走 P2 动作语义 | 目标恢复且连续 `n_recover` 帧有效 | 外推上限默认 1.0s，待确认 |
| 目标丢失 `> t_extrap_max` | 同上，丢失时长超过阈值 | L2 | 保持点（`last_valid` 或 `current_ego`） | 目标恢复并过确认 | 保持点来源可配置 |
| 目标 NaN/Inf | 位置/速度非有限数 | L3 | `no_plan_target_invalid` | 连续 `n_enter` 帧合法后开始恢复 | 不继续拿 NaN 算几何 |
| 目标越界 | `|x|/|y| > max_xy`、`z > max_alt` 或 `z < target_min_alt` | L3 | `no_plan_target_invalid` | 合法目标恢复 | 目标输入越界，不是输出护栏 |
| 目标时间戳倒退 | 新 stamp 小于上一接受 stamp，或 stamp 超前于 now | 维持当前级别 | 丢弃该帧，`point=None`，`reason=frame_discarded_time_reversed` | 时间戳恢复递增 | 不直接降级；不参与计数 |
| 目标频率异常 | `FrequencyMonitor` 丢帧率超阈值 | 默认只标 `FREQ_ANOMALY` | 仍按当前级别输出 | 窗口滑过后自动消失 | 默认关闭；置为诊断标记，不替代时效判断 |
| 己方状态断流 | `validate_ego` 标 `MISSING`/`STALE` | L3 | `no_plan_ego_lost` | 己方状态恢复并过确认 | 己方异常优先 |
| 己方速度 NaN | `twist.linear` 非有限数 | L3 | `no_plan_ego_lost` | 速度恢复 | P1 几何不依赖己方速度，但仍拒绝坏数据 |
| 未知 action | 不在 7 个枚举里 | L3 | `point=None`，`reason=unknown_action` | 已知 action | 与 P2 一致，不降级成 HOVER |
| 指令 JSON 非法 | `validate_cmd` 解析失败/缺字段 | L3 | `reason=cmd_json_invalid` 等 | 合法指令 | 缺 `drone_id`/`action`、动作拼错都拒绝 |
| 输出 NaN/Inf | 护栏第 1 步 | 本帧 no_plan | `point=None`，`reason=guard_non_finite` | — | 不改变 FSM 级别，但本帧不出点 |
| 输出越界 | 护栏第 2/3 步 | 不降级 | 裁剪后的点 | — | 只裁剪，不改变 action |
| 输出跳变 | 护栏第 4 步 | 不降级 | 裁剪后的点 | — | 限制的是目标点之间的跳变 |
| 输出与目标过近 | 护栏第 5 步 | 不降级，但本帧不出点 | `point=None`，`reason=guard_target_too_close` | — | 只对 INTERCEPT/ATTACK |
| 输出 stamp 不递增 | 护栏第 6 步 | 不降级 | stamp 推到 `last_stamp + 1e-6` | — | 记录 `stamp_adjusted` |

说明：

- `MISSING`（完全没有目标）和 `STALE`（有过目标但过期）在降级表里都按
  “目标丢失”处理；FSM 用“距离最后一次可用目标的时间”判断 L1/L2。
- `OUT_OF_BOUNDS` 在异常分类里映射为 `INVALID`，日志 reason 仍保留
  `target_out_of_bounds`，便于定位。
- 频率异常默认关闭（`freq_anomaly_enabled=False`）；开启后只做诊断标记，
  不单独把级别推到 L1/L2。原因：从 10Hz 掉到 1Hz 时，目标年龄本身也会
  很快变成 `STALE`，时效判断已经能覆盖；频率标记用于日志和后续标定。

## 5. 输出安全护栏顺序

`apply_safety_guard()` 严格按下面顺序执行：

1. **NaN/Inf 检查**：非法点直接拒绝，`reason=guard_non_finite`；
2. **XY 边界裁剪**：`|x|, |y| <= max_xy`；
3. **高度按模式裁剪**：TRACK/INTERCEPT 用 `safe_alt`（默认 5m），
   ATTACK 用 `min_alt`（默认 3m），上限 `max_alt`（默认 50m）；
4. **跳变限制**：`|p_goal - p_prev_goal| <= max_step`；恢复期用
   `max_step_recover` 起步，按 `n_recover_step` 逐步放开；
5. **与目标最小距离检查**：只对 INTERCEPT/ATTACK 生效，太近拒绝，
   `reason=guard_target_too_close`；
6. **时间戳单调性**：输出 stamp 必须严格大于上一帧，时钟抖动时把
   stamp 推到 `last_stamp + 1e-6`，记录 `stamp_adjusted`。

为什么顺序不能换：

- 先限制跳变再裁高度，可能把点拉回包线外；
- 先查最小距离再裁剪，可能把点裁到目标身上；
- 时间戳检查放最后，前面每一步都不改变“这一帧是否有效”。

边界说明：

- 跳变限制是**目标点对目标点**（`p_goal - p_prev_goal`），不是
  “己方当前位置到目标点”；后者由 P2 的 `apply_constraints` 负责。
  两者同时配置时，护栏更保守，不会放宽 P2 的限制。
- 护栏假定 `p_prev` 是上一帧已经过护栏的点；如果调用方传入包线外的
  历史点，护栏优先保证本次输出在包线内。
- TRACK 不做最小距离拒绝：P2 契约规定 TRACK 只发目标预测点，近距离
  环绕由中枢做；如果在护栏里拒掉 TRACK，会改变 P2 语义。
- 护栏拒绝非有限点时，`PlanResult.level` 会标成 `NO_PLAN`，但 FSM
  级别不变；适配层应以 `point is None` 判断是否发布，不要只看 `level`。

## 6. 恢复逻辑

- `HOLDING → NORMAL` 需要连续 `n_recover` 帧有效；
- `NO_PLAN → HOLDING` 需要连续 `n_exit` 帧有效；
- 回到 NORMAL 的第一帧，`max_step` 临时收紧到 `max_step_recover`；
  如果配置了 `max_step`，再按 `n_recover_step` 帧线性放开；
- 恢复期再次异常：`fsm.recovering=False`，记录
  `RecoveryInfo(completed=False, reason="recovery_aborted")`；
- 恢复完成：记录 `RecoveryInfo(from_level, frames, elapsed, completed=True)`，
  适配层可从 `fsm.last_recovery` 或 `PlanResult.recovered_from/
  recovery_frames` 读取。

注意：恢复期第一帧的收紧只作用于“目标点之间的跳变”。己方到目标点的
单帧位移仍由 P2 的 `max_step` 约束；两者叠加时取更保守的结果。

## 7. 参数表（全部在 `PlanParams`，无硬编码）

| 参数 | 默认值 | 单位 | 作用 | 状态 |
| --- | --- | --- | --- | --- |
| `t_extrap_max` | `1.0` | s | L1 外推时间上限 | 待确认 |
| `n_enter` | `2` | 帧 | 连续异常多少帧进入更差级别 | 待确认 |
| `n_exit` | `1` | 帧 | L3 回 L2 所需连续有效帧 | 待确认 |
| `n_recover` | `3` | 帧 | 回 L0 所需连续有效帧 | 待确认 |
| `max_step_recover` | `0.2` | m/帧 | 恢复第一帧临时跳变上限 | 待确认 |
| `n_recover_step` | `5` | 帧 | 恢复期逐步放开 `max_step` 的帧数 | 待确认 |
| `freq_anomaly_enabled` | `False` | — | 是否启用丢帧率检测 | 待确认 |
| `freq_anomaly_threshold` | `0.5` | 比例 | 丢帧率阈值 | 待确认 |
| `freq_window_size` | `20` | 帧 | 丢帧率统计窗口 | 待确认 |
| `hold_point_source` | `"last_valid"` | — | L2 保持点来源 | 待确认 |
| `ego_timeout` | `1.0` | s | 己方状态最大年龄 | 待确认 |
| `target_min_alt` | `0.0` | m | 目标输入最低高度（低于按越界） | 待确认 |

外推/滞回默认值的直觉（20Hz 控制周期）：

- `n_enter=2` → 0.10s；`n_recover=3` → 0.15s；`n_exit=1` → 0.05s；
- `t_extrap_max=1.0s` 与 P1 的 `max_age` 对齐：`max_pred_age=0.5`
  之内正常发点，0.5～1.0s 外推，超过 1.0s 保持；
- `max_step_recover=0.2 m/帧` → 约 4 m/s，低于兜底 6 m/s。

这些只是“可跑、可解释”的初值，不是最终标定值。

## 8. `PlanResult` 上的降级信息

P3 在 P2 的 `PlanResult` 末尾增加了带默认值的字段，P2 的 58 项测试不受影响：

| 字段 | 含义 |
| --- | --- |
| `level` | `NORMAL` / `EXTRAPOLATING` / `HOLDING` / `NO_PLAN` |
| `anomaly` | `STALE` / `INVALID` / `TIME_REVERSED` / `EGO_LOST` / `FREQ_ANOMALY` / `CMD_INVALID` |
| `guard_notes` | 护栏裁剪记录，例如 `xy_clamped:...`、`step_clamped:...` |
| `output_stamp` | 护栏确认后的单调递增发布时刻 |
| `recovered_from` | 恢复期来源级别 |
| `recovery_frames` | 恢复期已过帧数 |

L3 的 `reason`：

- `no_plan_ego_lost`：己方断流/位置非法；
- `no_plan_target_invalid`：目标 NaN/Inf 或越界；
- `no_plan_target_stale`：已经降级到 L3 但目标仍只是过期（边界情况）；
- `no_plan`：其他无法降级的情况；
- `unknown_action`：动作不在枚举里（与 P2 一致）；
- `frame_discarded_time_reversed`：时间戳倒退帧，级别不变。

L1/L2 的 `reason`：

- L1 正常外推：沿用 P2 的 `intercept_point` / `fallback_tail` /
  `track_target_point`，用 `level=EXTRAPOLATING` 区分；
- L1 几何无解回退保持：`hold_fallback_<p2_reason>`；
- L1 连最后目标都没有：`hold_fallback_no_extrapolation`；
- L2：`hold_last_valid` / `hold_current_ego`。

适配层（`algorithm_node.py`，P4 再接线）可以直接按 `level` / `anomaly` /
`guard_notes` 打 ROS 日志，不需要再解析自然语言。

## 9. 与 P2 七动作契约的关系

| 动作 | NORMAL | L1 | L2 | L3 |
| --- | --- | --- | --- | --- |
| `TRACK` | 目标预测点 | 外推后的目标点 | 保持点 | no_plan |
| `INTERCEPT` | 拦截点 / 尾随点 | 外推后的拦截点 / 尾随点 | 保持点 | no_plan |
| `ATTACK` | 拦截点 / 不打点 | 拦截点；无解时**显式保持点** | 保持点 | no_plan |
| `TAKEOFF` / `HOVER` / `RETURN` | 中枢生成，P3 透传 | 同左，不驱动 FSM | 同左 | 同左 |
| `RESUME_PATROL` | `resume_patrol_unspecified` | 同左 | 同左 | 同左 |
| 未知动作 | — | — | — | `unknown_action` |

关键点：ATTACK 在 L1/L2 都**不会**输出尾随点。L1 拦截无解时用显式
保持点（与适配层现有 ATTACK 兜底一致），L2 用保持点；两者 `reason`
都以 `hold_` 开头，不会伪装成 `intercept_point`。

## 10. 已知限制与接口待确认

### 10.1 已知限制

- **中枢没有显式 no_plan 语义**：`plan_callback` 只在收到新 JSON 时更新
  `latest_plan_targets`；超过 2 秒没更新才清空。规划“不出点”时，中枢
  会继续用上一帧点，最长 2 秒。P3 只能把 `no_plan` 表达清楚，是否补发
  保持点由 P4 适配层决定。
- **E/F 同名话题自回灌**：中枢会把 `/{drone_id}/state` 再转发一次；
  若规划也订阅同一 topic，己方状态时间戳可能是旧的，新鲜度判断不可靠。
  P3 在 `validate_ego` 里记录这个风险，不处理自回灌。
- **规划延迟口径不一致**：接口文档写“规划延迟 > 0.5s 丢弃”，中枢实际
  是 `max_plan_delay = 0.8s`；P3 不依赖这个阈值，但 P4 要对齐。
- **中枢 TRACK 分支优先用视觉目标**：`latest_vision_target` 存在时，
  中枢 TRACK 不读规划的 `my_plan`；因此 P3 在 TRACK 下的外推/保持点
  是否真的被执行，取决于中枢当时的视觉状态。这属于 P4 联调确认项。
  三个场景的仿真中，TRACK 场景的 P3 点与中枢实际指令最大偏差达到
  19.7m，说明 TRACK 下 P3 点可能完全不被执行；见
  `文档/P3三个复杂场景仿真.md`。
- **默认 `max_step=None` 时旧指令保留风险更大**：仿真中 ATTACK 场景
  己方断流 0.5s，默认参数下飞机仍沿中枢保留的旧指令飞了 5.58m；
  把 `max_step` 标定到 0.62m/帧后，L3 期间飞行距离为 0m。`max_step`
  不只是输出平滑，也间接限制“中枢保留旧点”的盲飞距离。

### 10.2 八个接口问题（先给默认值，不阻塞纯算法）

| # | 问题 | 是否阻塞 P3 纯算法 | 当前默认策略 |
| --- | --- | --- | --- |
| 1 | 目标丢失后降级策略由谁定？外推多久？和 `max_pred_age` 什么关系？ | 不阻塞 | P3 先定：0.5s 内正常，0.5～1.0s 外推，>1.0s 保持；`t_extrap_max=1.0` |
| 2 | 中枢收到 no_plan 的语义：保持、悬停还是 Failsafe？ | 阻塞 P4 接线，不阻塞纯算法 | P3 只返回 `point=None + reason`；适配层可沿用“ATTACK 发当前位置保持点”的兜底 |
| 3 | 规划延迟 0.5s 从哪个时间戳算到哪个时间戳？ | 不阻塞纯算法 | 输入端按“目标源 stamp → now”算 age；输出 stamp 用发布时刻 now；注意中枢实际阈值是 0.8s |
| 4 | `MAX_XY/MAX_ALT/MIN_ALT/H_safe` 由谁下发？ | 阻塞“单一事实源”，不阻塞纯算法 | 暂与中枢常量保持一致：1000/50/3/5；后续由参数服务器或配置文件统一 |
| 5 | 频率异常定义：10Hz→1Hz 算不算？丢帧率阈值？ | 不阻塞 | 默认关闭；开启后窗口 20 帧、阈值 0.5，10Hz→1Hz 会命中，窗口滑过后恢复 |
| 6 | 己方状态断流时是否直接 L3？ | 不阻塞 | 是；经过 `n_enter=2` 帧确认后进 L3（第一帧本来也不会发点） |
| 7 | `t_extrap_max` 初值建议？ | 不阻塞 | 1.0s，与 P1 `max_age` 对齐 |
| 8 | `N_recover/N_enter/N_exit` 初值建议？ | 不阻塞 | `n_enter=2`、`n_exit=1`、`n_recover=3`；20Hz 下分别 0.10/0.05/0.15s |

第 2 条是唯一会直接影响 P4 行为的问题：如果中枢以后支持“显式清空/悬停”，
适配层就可以不再补保持点；如果不支持，就需要保留当前兜底。
