## 3. 裁决 2/3 的实验与结论

用户裁决（m00185）：裁决 1 取 A；裁决 2/3 由我选择，但必须先测试、在文档与代码注释

### 3.1 裁决 3：`max_step` 默认值

用 `simulate_p3.py` 复现三个场景，只改 `params.max_step`，20Hz + 中枢 2s 保留模型：

| 场景 | max_step=None | 0.30 | 0.38 | 0.62 | 1.00 |
|---|---|---|---|---|---|
| A TRACK 跳变 / 盲飞 / 最小距 | 0.926 / 3.300 / 1.48 | 0.300 / 3.300 / 1.48 | 0.380 / 3.300 / 1.48 | 0.620 / 3.300 / 1.48 | — |
| B INTERCEPT 跳变 / 盲飞 / 尾随 | 6.100 / 0.000 / 107 | 0.300 / 0.000 / 107 | 0.380 / 0.000 / 107 | 0.620 / 0.000 / 107 | 0.760 |
| C ATTACK 跳变（准备发布点）/ 盲飞 / 最小距 | 68.751 / 5.580 / 8.59 | 0.300 / — / **50.40** | 0.380 / — / **44.80** | 0.620 / **0.000** / 15.83 | 0.760 / — / 15.15 |

结论：**单值 0.62**。原因：

- `0.62 = v_max_attack 12.4 m/s × 0.05s`，是保证 ATTACK 可达的下限；用 0.30/0.38
  会把 ATTACK 实际速度压到 6/7.6 m/s，最小目标距离退化到 50.4/44.8m，等于追不上。
- 按模式取 0.30/0.38/0.62 只让 TRACK/INTERCEPT 的 P3 点更平滑；TRACK 点当前不被
  中枢执行（见 3.2），INTERCEPT 的盲飞与能力不变，收益不足抵复杂度。
- 0.62 同时把 L3 期间“中枢保留旧点”的盲飞距离压到 0（仿真），是安全收益最大的一档。

代码：`launch/algorithm.launch.py` 与 `adapter_core.py` 的 `# !` 注释记录了上述理由。

## 10. 已知问题（不在 P4 修）

1. **E/F 自回灌**：中枢每 20Hz 把缓存的 `/{drone_id}/state` 重发到同名 topic
   （`center_node.py:651`）。适配层按 `header.stamp` 判新鲜，桥接断流后旧 stamp
   仍会被识别为 STALE；但 stamp=0 的状态帧只能退回接收时刻，此时“断流”不可检测。
2. **`no_plan` 不是立即刹车**：中枢保留旧规划点最多 2.0s（实测 1.98s）。L3 不发布
   只是“不再刷新”；靠 `max_step=0.62` 把盲飞距离压到 0（仿真），不是真刹车。
3. **TRACK 优先视觉**：视觉新鲜时中枢不执行 P3 的 TRACK 点（实测偏差 14.14m，
   仿真 19.7m）。P4 只记录，不改中枢。
4. **RESUME_PATROL / 未知 action**：中枢会写入模式并发布 `/action`，但状态机无分支，
   该机此后不再收到 setpoint。已在 P4 记录，需中枢 owner 决策。
5. **接口 C 的 action 不是控制输入**：`plan_callback` 不解析 action；限幅切换走
   自己的模式与接口 H。`课题二内部接口规范.md:83` 的“ATTACK 强制解除限幅”未落地。
6. **延迟口径**：文档写 0.5s，中枢实现 `max_plan_delay=0.8s`，且中枢用
   `time.time()` 判规划延迟、ROS clock 打 stamp。P4 规划侧按 0.5s 设计。
7. **mock 速度上限**：dry bridge 为 10/6/3 m/s，低于配置 12.4/7.6/6.0；标定表按
   实际链路记录（裁决 1 A），真机可达速度待 SITL/试飞。
8. **两层 max_step**：P2 的 `apply_constraints` 以己方当前位置为基准限幅，P3 护栏
   以 `fsm.last_valid_point` 为基准再限一次；静态己方下点会停在 `own+0.62`。
9. **目标时间戳回退/未来/零**：在适配层入口丢弃（不进入样本队列），不驱动 P3 的
   `validate_target` 分支；P3 的该分支仍由单测覆盖。己方时间戳回退则交给 P3，
   走 `frame_discarded_time_reversed`，不计数。
10. **文档冲突**：Humble 指南“ATTACK 无解不发点”与 P2/P3/代码“发保持点”不一致；
    Humble 指南 §6.4 列了 launch 未暴露的参数（P4 已补齐）；中枢早期说明称
    RESUME_PATROL“保持原态”，代码实际写入模式。P4 以实现为准并在此登记。
