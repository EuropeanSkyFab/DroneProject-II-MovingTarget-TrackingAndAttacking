# 算法测试基本方法

本文件只讲测试：分层、命令、判据、图表和排障。算法行为、接口和参数见 [algorithm_pkg/README.md](../README.md)。

测试分五层，底层不通过时，上层结果不可用：

| 层 | 数量 | 内容 | 耗时 |
|---|---:|---|---|
| 单元测试 | 239 | 几何、策略、降级、护栏、适配、参数、视觉门 | 秒级 |
| 情景测试 | 20 | 单点行为 7、场景定义 8、视觉门 5 | 秒级 |
| 多帧仿真 | 8 | 追逃降级、L3 保持、短遮挡 / 尾随 / ATTACK 保持、级别覆盖汇总、3D 爬升、双机主攻/警戒 | 秒级 |
| 联调脚本 | 3 个 | 节点冒烟、失效注入、多机隔离 | 分钟级 |
| 物理仿真 | 4 个场景 + 探针 | PX4/Gazebo 闭环、桥接限幅、DDS | 分钟级 |

## 1. 执行命令

从仓库根目录执行。纯 Python 测试不需要 ROS，不需要 launch。

```bash
# 全部
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q src/algorithm_pkg/test

# 单元测试，不出图
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/unit

# 情景测试，出图
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/scenario \
    --scenario-chart-dir /tmp/algorithm_scenario_charts

# 多帧仿真，出图
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/sim \
    --scenario-chart-dir /tmp/algorithm_scenario_charts

# 单条用例
PYTHONPATH=src/algorithm_pkg /usr/bin/python3 -m pytest -q \
    src/algorithm_pkg/test/unit/test_safety_guard.py::test_step_limited
```

全量应为 267 passed，情景和多帧应生成 25 张图。默认图目录是 `/tmp/algorithm_scenario_charts`。Humble 容器里 `colcon test` 也应得到 267 tests、0 errors、0 failures、0 skipped。

测试结束会打印“算法实测结果”，每条用例三行：场景、预期、实测。`measured()` 记录运行时的实际数值。只看通过条数不够，调试时加 `-s` 看 print，或加 `--pdb` 进失败帧。

## 2. 层怎么选

| 要验证的事 | 放哪层 | 例子 |
|---|---|---|
| 给定输入，函数返回什么点、什么原因 | unit | 拦截方程判别式、护栏裁剪、HOVER 锚点 |
| 连续多帧级别是否抖动、是否停在上一帧点 | scenario 或 sim | 0.6 s 遮挡进 L1、1.5 s 丢失进 L2、断流进 L3 |
| 两个 ROS 节点的字段、时间戳、话题是否正确 | scripts/p4 | JSON 字段、多机串号、时钟差 |
| PX4/Gazebo 闭环、桥接限幅、DDS 时延 | 物理仿真 | 场景执行器、探针 |

一个用例既不能断言精确值，也不能推进时间，说明测试目标还没写清。

## 3. 单点行为

`test/scenario/test_scenario_behavior.py`，7 条，均出图。

| 用例 | 机制 | 断言重点 |
|---|---|---|
| 1 HOVER 无目标 | 进入 HOVER 捕获锚点 | 发点固定，不跟己方漂移；stamp 用当前己方时刻 |

| 3 匀速目标 | 最小二乘拟合速度 | 预测点按目标速度外推 |
| 4 横穿目标 | 拦截方程两个正根 | 取最早可达根 |
| 5 目标更快且远离 | 无正根 | INTERCEPT 退尾随点，`d_tail=4.0 m` |
| 6 目标跑到身后 | 掉头判定 | INTERCEPT 判不可达，ATTACK 不判 |
| 7 目标消失 0.3 s | 缓存样本与外推 | `max_pred_age` / `t_extrap_max` 边界 |

`test/scenario/test_scenario_defs.py` 8 条，验证场景注册表、轨迹、指标和判定口径，不出图。

视觉门 5 条：

- `test_vision_delay_gate.py`：0.50 s 超阈值、0.55 s 进 L1、1.50 s 进 L2。
- `test_vision_mock_gate.py`：0.3 s 延迟 + 0.1 m 噪声 + 0.4 s 丢帧。
- `test_vision_mock_maneuver.py`：转弯目标，级别保持 NORMAL 但位置滞后。

mock 参数是假设值。真实视觉链路未交付，不能把 mock 通过写成真实视觉通过。

## 4. 多帧仿真

`test/sim/`，8 条，均出图。

| 文件 | 场景 | 覆盖 |
|---|---|---|
| `test_multiframe_degrade.py` | 追 5 s、目标丢 1.5 s、己方断流 0.5 s、重捕 | L1→L2、L3、恢复、重捕命中 |
| `test_l3_hold_fallback.py` | 目标速度变 NaN，己方有效 | L3 固定保持点，不发上一帧目标点 |
| `test_multiframe_scenarios.py` | 短遮挡、追不上尾随、ATTACK 保持 | 3 条多帧场景 |
| `test_multiframe_scenarios.py::test_multiframe_level_coverage_summary` | A/B/C 的 L1/L2/L3 帧数 | 1 张汇总柱状图 |
| `test_multiframe_3d.py` | 目标爬升，TRACK 跟三维预测点 | 过程图 + 1 张 3D 路径图 |
| `test_multiframe_dual.py` | 双机同目标，主攻 ATTACK + 警戒 HOVER | 1 张双机图 |

三类多帧场景的断言：

| 用例 | 时间线 | 断言 |
|---|---|---|
| `test_multiframe_track_short_occlusion` | TRACK，目标转向，2.0～2.6 s 遮挡 | 2.05 s 进 L1；2.65 s 恢复确认 HOLDING；2.75 s 回 NORMAL |
| `test_multiframe_intercept_unreachable_tail` | INTERCEPT，目标 9 m/s 远离，3.0～4.5 s 丢失 | 可见期 `fallback_tail`；4.0 s 进 L2 并固定锚点；恢复后继续尾随 |
| `test_multiframe_attack_loss_dropout` | ATTACK，目标转向，2.0～2.8 s 遮挡，2.3～2.8 s 己方断流 | `hold_attack_no_solution`；L3 不发点；2.85 s 恢复 HOLDING |

多帧测试用固定基线参数：`v_max=4.50`、`v_max_intercept=7.60`、`v_max_attack=14.80`、`max_step=0.74`。生产 launch 用 `v_max_attack=12.40` 和分档步长 0.14 / 0.38 / 0.62。这条差异是有意的：多帧测试用单值基线保持时间线稳定，生产参数由 unit 测试覆盖。

纯 Python 多帧不模拟中枢 2 s 保留，也不模拟飞控动力学。中枢保留、DDS 时延和桥接限幅放到物理仿真验收。

## 5. 图表规范

图是测试证据，不参与断言。unit 测试不加载 matplotlib；scenario 和 sim 用例必须出图。

默认输出到 `/tmp/algorithm_scenario_charts`，系统清理 `/tmp` 后需要重新跑测试。要长期保留，把 `--scenario-chart-dir` 指到仓库内的本地目录，例如 `.p5/evidence/charts`。生成图不入库，`.p5/` 不随包交付。

### 5.1 图型选择

| 图型 | 适用条件 | 结构 |
|---|---|---|
| 过程图 | 时间跨度 ≥0.25 s，且帧数 >3 | A 距离、B 俯视图、C 速度或发点偏差、D 级别 |
| 判定图 | 单帧，或时间跨度 <0.25 s，或帧数 ≤3 | x-y 几何、关键点、最终级别/reason、参数和判据 |
| 柱状图 | 多用例汇总 | 级别覆盖、数量对比；每套测试最多 1 张，不放到单条用例 |
| 双机图 | 两机角色固定（主攻/警戒） | 3D 或俯视路径 + 到目标距离；主攻、警戒两条轨迹 |

单帧用例不许画时间序列。0.05 s 的横轴、几乎不动的三条线，读者看不出结论。

3D 图按 z 变化自动判断：z 最大值和最小值差超过 0.5 m 时，另出一张同名 `__3d` 图，包含 3D 路径、地面投影和 x-y 顶视图；过程图 B 面板仍画俯视图，并注明“3D 见同名 __3d 图”。

### 5.2 过程图

过程图固定 2×2 四面板，标题用 `A.`～`D.` 开头。

1. **A 距离**：己方到目标真值的距离；画 0.5 m 命中门限；最近点标数值和时刻。
2. **B 俯视图**：己方轨迹、目标真值、规划发点三条线；x/y 非等比例时写清；y 方向不变时标“y 方向不变”；z 有变化时注明 3D 图文件名。
3. **C 速度或发点偏差**：己方有移动时画速度，标峰值；己方静止时改画“发点-己方 x 差”，看规划点领先还是滞后。
4. **D 级别**：L0～L3 阶梯，事件竖线；L1/L2/L3 进入时刻写图底。

阶段底色只标输入不可用、遮挡、断流这类阶段；同一阶段只用一种颜色，图底给图例。事件原因写图底事件行，不堆在面板里。

图底必须写：测试名、数据来源、事件列表、“图只作证据，不参与断言”。

### 5.3 判定图

判定图只画几何关系，不画时间轴。

1. 画己方、目标真值、规划发点，点和轨迹都要有中文标签。
2. 目标有速度时画速度箭头；目标转向时画转向后的方向。
3. 尾随点、原始拦截点、本帧发布点这类关键点单独标注；尾随场景同时标 `d_tail` 和 `max_step` 截断。
4. 无解场景加追击能力小图：目标 `x = x0 + v_target·t`，己方 `x = v_own·t`，两线不相交才说明“无正根”。
5. 左上角放“最终：级别 / reason”小框；原始 reason 只放这里和图底，不放主标题。
6. 轴范围至少留 2 m 余量；点不能贴在边框上。

单帧判定图不写“时间（s）”轴。需要时间过程时改用过程图。

### 5.4 标题、标注和配色

- **主标题**：一句结论，例如“目标 10 m/s 远离：INTERCEPT 无解，发目标后方 4 m 尾随点”。不写测试函数名，不写 `fallback_tail` 这类内部字段。
- **副标题**：参数、动作、判据、数据来源，一行说清。
- **面板标题**：`A. 距离：最近点与 0.5 m 门限` 这种短句，不写“面板 A”。
- **数值标注**：最近距离、峰值速度、阈值、L1/L2/L3 时刻直接标在图上；图底再列事件原因。
- **配色**：己方蓝色实线，目标橙色虚线，发点红色空心点，L3 红色，L2 灰色。颜色之外再用线型和标记区分。
- **字号与线宽**：面板标题 9.5～10 pt，图例 7.5～8.5 pt；级别线 0.5 pt，己方轨迹 2 pt，目标 1.1 pt。
- **禁止**：双 y 轴、旋转 90° 的长说明、标签压线、文字跑出坐标轴、用 Gazebo 截图代替过程图。

### 5.5 3D 规则

3D 图是数据图，不是 Gazebo GUI。禁止恢复 Gazebo GUI，也禁止用 Gazebo 截图代替过程图。

- z 变化超过 0.5 m：另出 `__3d` 图，左侧 3D 路径和地面投影，右侧 x-y 顶视图。
- z 变化不超过 0.5 m：不另出 3D 图，过程图 B 面板注明“高度省略”。
- 3D 轴标 x 东、y 北、z 高，单位 m；x/y 非等比例时写清。
- 3D 只用于 xyz 都有变化的数据；不要把平面轨迹硬画成 3D。
- `figures/` 的 4 张参考图只作样式参考，不参与测试。

### 5.6 测试侧写法

情景和多帧用例用 `scenario_chart` fixture。每条出图用例必须调用 `configure` 写主标题和副标题；需要判定图时设 `mode="decision"`，需要汇总柱状图时设 `mode="bar"`。

```python
scenario_chart.configure(
    headline="目标 10 m/s 远离：INTERCEPT 无解，发目标后方 4 m 尾随点",
    subtitle="目标 (30,0,10)，v_max_intercept=7.60 m/s，d_tail=4.0 m。",
    mode="decision",
    decision={
        "extra_points": [(26.0, 0.0, "尾随点原值 (26,0)", "#2E7D32", "*")],
        "pursuit": {
            "target_x0": 30.0, "target_speed": 10.0,
            "own_speed": 7.60, "duration": 8.0,
        },
    },
)
```

己方断流、动作锚点这类需要真实己方位置的用例，`add` 时额外传 `own_truth`，否则距离和速度面板会缺帧。

汇总柱状图由单独测试生成，例如 `test_multiframe_level_coverage_summary`；柱状图数据必须和断言同源，不能手写一份和测试无关的数字。

图不参与断言。用例的通过条件由数值断言决定；图只回答“人能不能看懂”。

### 5.7 验收清单

出图后逐张检查：

- [ ] 主标题是结论，不是测试函数名或内部 reason。
- [ ] 副标题有参数、动作、判据。
- [ ] 面板有 A/B/C/D 标题，单位和中文标签齐全。
- [ ] 关键数值直接标在图上，最近点、峰值、阈值、L1/L2/L3 时刻都有。
- [ ] 阶段底色和事件竖线存在，事件原因在图底。
- [ ] 判定图没有时间轴；过程图没有单帧硬画时间序列。
- [ ] z 变化超过 0.5 m 时有 `__3d` 图；平面轨迹没有硬画 3D。
- [ ] 标签不重叠、不跑出坐标轴，图没有被 `bbox_inches` 撑成异常长宽比。
- [ ] 图底有测试名、数据来源、“图只作证据，不参与断言”。
- [ ] 一个没看过上下文的人，能只靠图回答：发生了什么、关键数值是多少、为什么是这个结果。

不满足的图先改图，不改断言迁就图。

## 6. 排障

### 6.1 级别抖动

先看级别变化日志：

```bash
grep "降级级别变化" algo.log
```

`NORMAL→L1→L2→NORMAL` 在 1 秒内反复出现，通常是目标源在过期边界附近波动，或 `max_pred_age` 接近源帧率。先确认源帧率和时间戳，再调阈值。

### 6.2 发点抖动

按顺序查：

1. 目标输入本身是否抖动。
2. 策略层输出是否抖动：动作或目标预测变化。
3. 输出约束是否生效：开 debug 日志，看 `xy_clamped`、`z_clamped`、`step_clamped`。
4. 两层 `max_step` 谁在限制：策略层以己方位置为基准，输出约束以上一帧发布点为基准，取更保守的结果。

`max_step=0` 表示不限幅，只用于调试。生产值按动作分档。

### 6.3 本帧不发点

先确认包是否发布：

```bash
ros2 topic echo /planning/target_pose --once
ros2 topic hz /planning/target_pose
```

未发布时查日志：

```bash
grep "本帧不发点" algo.log | tail -20
```

| reason | 含义 | 检查项 |
|---|---|---|
| `target_missing` | 未收到任何目标 | 目标源话题、QoS、命名空间 |
| `target_invalid` | 目标 NaN、越界或时间戳非法 | 视觉输出、坐标系、边界参数 |
| `target_too_old` | 预测年龄超过 `max_pred_age` | 源帧率、时钟、阈值 |
| `own_invalid` | 己方位置缺失或非有限值 | `/drone_x/state`、桥接 |
| `velocity_unavailable` | INTERCEPT/ATTACK 还没估出速度 | 目标至少两帧、时间跨度 |
| `attack_no_solution` | ATTACK 无解，正常降级 | 不是缺陷 |
| `no_plan_ego_lost` | L3：己方状态中断或非法 | `/drone_x/state`、`ego_timeout` |
| `no_plan_target_invalid` | L3：目标 NaN 或越界 | 视觉输出、边界参数 |
| `no_plan_target_stale` | L3：目标仅处于过期状态 | 源帧率、时钟 |
| `hold_*` | 保持点，正常降级 | 不是故障 |

### 6.4 发布后没执行

问题通常在中枢侧，按顺序查：

1. 中枢保留上一帧点最多 2 s。停止发布后飞机会继续飞一段。
2. TRACK 下中枢优先使用视觉目标，忽略规划点。
3. `action` 不是控制输入，不驱动中枢模式或限幅。
4. 中枢 `max_plan_delay=0.8 s`，本包 `stamp` 是源头时刻，时钟不同步会被丢弃。

用 `ros2 topic echo /<drone_id>/setpoint_raw/local` 看中枢是否发布、发布内容。若中枢持续发上一帧点，问题不在本包。

### 6.5 时间戳被丢弃

日志示例：

```text
丢弃视觉帧：stamp_zero
丢弃视觉帧：stamp_future
丢弃外部目标帧：stamp_reversed
```

排查顺序：发布端是否使用 ROS clock；是否有两个时钟源；是否有回灌的过期时间戳；首帧时间戳是否为 0。被丢弃是正确行为，应修发布端。

## 7. 缺陷处理

1. 先写能复现缺陷的失败测试。docstring 写清场景和预期。
2. 确认失败原因与现场一致。原因不一致说明复现错了。
3. 只改必要位置，不做无关重构。
4. 跑全量测试，条数以 `pytest --collect-only` 为准。
5. 涉及场景指标时，对比修改前后的距离、跳变、级别分布。
6. 真机前先跑 `scripts/p4/smoke_node.py`，再跑单机闭环，最后做失效注入。

不得修改断言迁就代码。断言本身错误时，单独说明依据，不能为通过而删除条件。修改阈值必须写依据：真机数据、数据来源、物理量换算。

## 9. 物理仿真验收

### 9.1 环境

在 `p5_sitl` 容器内运行。容器包含 ROS 2 Humble、Gazebo Harmonic、PX4 v1.17 和 Micro-XRCE-DDS Agent。图表中文需要 `fonts-noto-cjk`。环境搭建见 [Jazzy开发与Humble交付指南](Jazzy开发与Humble交付指南.md)。

宿主机只做编辑和纯 Python 测试。ROS 构建、launch 和 Gazebo 都在容器内。

`.p5/` 是本地仿真工作区，不随包交付。

### 9.2 同步与构建

容器里的算法包是独立副本，不会自动跟随 `src/algorithm_pkg`。改完先同步再编译：

## 11. 跨模块问题反馈

### camera relay 无法启动

- 现象：`ros2 run flight_ctrl_pkg camera_relay_node` 退出码 1，`/drone_1/camera/image_raw` 无数据。
- 根因：运行时 protobuf 7.36.2 与系统 `gz.msgs10` 生成代码不兼容。
- 归属：飞控调试模块；环境维护协同。
- 本包处理：不修。真实视觉验收被阻塞。

### 6 m/s 横穿目标追不上

- 现象：4 m/s 目标可命中，6 m/s 目标最近约 5～10 m。
- 根因：策略层按己方位置裁剪规划点，桥接 P 项和前馈有自己的上限。组合后实际追速约 4～6 m/s。
- 归属：规划裁剪语义和桥接控制回路。
- 本包处理：不单独修。验收写“4 m/s 保证，4～6 m/s 不保证，6 m/s 以上不支持”。

## 12. 测试维护约定

- 新增用例先判断层，再放目录。unit 不放多帧循环，scenario 不出图不算完成。
- 情景测试必须用 `scenario_chart` fixture，图不出算测试没做完。
- 断言期望行为，不迎合现状。发现缺陷先判断测试错还是算法错。
- 改语义、改断言、删用例，先写清依据，再改代码。
- 测试文件不依赖 `/tmp` 绝对路径。图目录用 `--scenario-chart-dir` 或环境变量。
- 不把 `.p5/` 本地产物写进断言或交付物。
